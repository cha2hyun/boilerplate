# 언어와 표시 통화

앱은 `en-US`와 `ko-KR`, 표시 통화 `USD`와 `KRW`를 지원합니다. 기본값은 영어와 USD이며 언어와 통화는 독립적입니다. 한국어를 선택해도 통화가 자동으로 바뀌지 않습니다. 형식·정밀도는 [숫자 표시](number-formatting.md), 긴 문구·날짜·방향성은 [국제화 디자인](design/international-design.md)이 소유합니다.

`widgets/app-shell`이 헤더의 언어·표시 통화 메뉴를 소유합니다. 언어는 Globe, 통화는 지폐 모양의 [Lucide Banknote](https://lucide.dev/icons/banknote)를 사용합니다. 같은 크기의 아이콘 버튼을 언어, 통화 순서로 한 줄에 정렬하고 shadcn DropdownMenu의 라디오 항목으로 현재 선택을 표시합니다. 통화를 선택하면 메뉴가 닫히며, Escape로 닫으면 초점이 해당 버튼으로 돌아갑니다. 환율·오류 안내와 재시도는 통화 메뉴를 열었을 때만 표시하며 재시도 중에는 메뉴를 유지합니다.

## 번역과 환경 설정

[`react-i18next`의 `useTranslation`](https://react.i18next.com/latest/usetranslation-hook)을 `@/shared/lib/i18n`에서 가져옵니다. `common`, `workspace`, `admin`, `examples`, `orderEditor`, `customerEditor`, `demoLogin`, `workspaceUsers` namespace를 두 언어 모두 번들에 포함합니다. 초기화의 namespace 목록은 실제 영어 resources에서 파생하여 중복 목록의 불일치를 막습니다. 번역 파일을 네트워크에서 추가로 가져오지 않습니다. 영어 리소스로 키를 타입 검사하며 기본 fallback은 `en-US`입니다. fallback이 빠진 한국어 문구를 숨기지 않도록 테스트에서 전체 키와 interpolation 변수 일치를 별도로 검사합니다.

```tsx
import { useFormatters, useTranslation } from '@/shared/lib/i18n'

function OrderCount({ total }: { total: number }) {
  const { t } = useTranslation('admin')
  const { formatNumber } = useFormatters()
  return <p>{t('orders.count', { total: formatNumber(total) })}</p>
}
```

문장은 완성된 단위로 번역하고 값은 interpolation으로 전달합니다. 헤더, 메뉴, 상태, 검색 placeholder, 빈 화면, 오류, 토스트, aria-label도 리소스를 사용합니다. 컴포넌트 밖에서 번역된 문자열을 고정하지 않습니다. 상태 코드와 API 필드 값은 유지하고 표시 시 알려진 값에 대응하는 키를 선택합니다. 이름, 이메일, 주소, 프로젝트 입력, 메시지 본문 같은 사용자·백엔드 콘텐츠는 자동 번역하지 않습니다.

`shared/lib/i18n/preferences.ts`의 Zustand store는 `blueprint-locale-preferences`에 버전 1의 `{ state: { locale, currency }, version }`만 저장합니다. 저장 시와 복원 시 지원 enum을 검증하며 잘못된 JSON·값·버전은 `en-US`/`USD`로 복구합니다. 브라우저 저장소가 막히면 현재 세션의 메모리 설정을 유지합니다. 다른 데이터나 환율은 이 store에 넣지 않습니다.

저장 key/version은 Provider를 초기화하지 않는 `shared/config/preference-keys.ts`가 소유합니다. 언어 store와 [앱 오류 복구](error-handling.md)가 같은 상수를 사용하므로 새 제품에서 이름을 바꿀 때 한 곳에서 갱신합니다.

`app/providers/localization-provider.tsx`가 선택 언어를 i18next와 `<html lang>`에 연결합니다. 두 지원 언어는 LTR이며 RTL 지원은 포함하지 않습니다. `useFormatters()`와 `NumberDisplay`는 선택 언어를 구독합니다. Foundations처럼 의도적인 비교에는 명시적 `locale` 옵션을 사용합니다.

## 실제 환율과 캐시

USD→KRW 변환은 [Frankfurter의 단일 통화쌍 API](https://frankfurter.dev/#rate)인 `https://api.frankfurter.dev/v2/rate/USD/KRW`에서 받은 값을 사용합니다. 공개 API는 키 없이 호출할 수 있으며 일별 기준 데이터를 제공합니다. 기본 응답은 여러 제공자의 데이터를 혼합한 값으로 실시간 거래 체결 가격을 뜻하지 않습니다. API 기준 날짜는 응답 검증과 캐시에 보존하지만 메뉴에서는 날짜와 설명 문단을 생략합니다. 특정 숫자를 앱의 고정 환율로 사용하지 않습니다. [Frankfurter 문서](https://frankfurter.dev/)가 제공 방식과 갱신 주기의 기준입니다.

`entities/exchange-rate`가 Zod 스키마와 Query 옵션을 소유합니다. `base: 'USD'`, `quote: 'KRW'`, 실제 ISO 날짜, 양수이면서 유한한 `rate`를 확인합니다. 기존 `createApiClient`를 재사용하므로 JSON 검증, 15초 제한, AbortSignal, HTTP/네트워크 오류 계약을 공유합니다. credentials와 referrer를 보내지 않습니다. 별도 API 키나 환경 변수는 필요하지 않습니다.

| 항목             | 계약                                                             |
| ---------------- | ---------------------------------------------------------------- |
| Query 키         | `['exchange-rates', 'frankfurter', 'v2', 'USD', 'KRW']`          |
| 신선도           | 6시간 (`staleTime`)                                              |
| 미사용 캐시 보관 | 24시간 (`gcTime`)                                                |
| 자동 재시도      | 일시 실패 최대 1회; 잘못된 응답과 HTTP 4xx는 재시도하지 않음     |
| 저장 위치        | TanStack Query 메모리 캐시; Zustand/localStorage에 복제하지 않음 |

동시 소비자는 같은 요청과 캐시를 공유합니다. 정상 응답이 없는 최초 로딩/실패에서는 KRW 금액을 `—`로 표시하며 임의 환율을 사용하지 않습니다. 이미 검증된 캐시가 있으면 갱신 중이나 갱신 실패에도 그 값을 유지합니다. USD 표시는 환율 없이 사용할 수 있습니다. Query의 신선도는 앱의 재요청 시점이며 환율 기준 날짜가 오늘이라는 보장은 아닙니다.

`app/providers/currency-provider.tsx`가 앱 셸에서 Query 결과를 shared context에 주입합니다. 독립된 로그인 화면은 공개 샘플의 USD 금액을 언어에 맞춰 표시하므로 환율을 조회하지 않습니다. shared formatter는 entity를 가져오거나 자체 fetch를 하지 않습니다. demo의 MSW는 이 외부 요청을 통과시키므로 demo에서도 환율은 실제 API 데이터입니다. 고정 환율 응답은 단위/E2E 테스트에서만 사용하고 런타임 handler에 추가하지 않습니다.

## 금액의 단위와 표시 경계

현재 데모 금액의 원본 통화는 USD입니다. Overview KPI/수익 차트는 USD 주요 단위(달러), 주문 상품·배송비·고객 누적 금액은 USD cents입니다. 주문/고객 호출부는 먼저 `/ 100`으로 달러로 변환하고 `formatMoney()` 또는 `MoneyDisplay`에 전달합니다. 원본 API 값과 저장 데이터는 변경하지 않습니다.

```tsx
const { formatMoney } = useFormatters()
const displayedOrderAmount = formatMoney(orderTotalInCents / 100)
// USD: 원본 달러 금액. KRW: 원본 달러 금액 × 검증된 USD/KRW rate.
```

`formatMoney(valueUSD, options?)`와 `MoneyDisplay value={valueUSD}`가 선택 통화로 변환합니다. `MoneyFormatOptions`에는 `style`과 `currency`를 지정하지 않습니다. 정밀도·기호 숨김·축약 형식은 공통 숫자 formatter에 위임하며 중간값을 미리 반올림하지 않습니다. 일반 표시의 기본 정밀도는 USD 2자리, KRW 0자리입니다.

순수 `formatNumber()`의 `currency` 옵션은 이미 해당 통화 단위인 숫자의 형식만 바꾸며 환율을 적용하지 않습니다. 통화 전환이 필요한 금액에 `formatNumber(value, { currency: 'KRW', style: 'currency' })`를 사용해 변환을 대신하지 않습니다.

## 변경과 검증

새 문구는 양쪽 언어 파일에 같은 키와 변수를 추가합니다. 새 금액은 원본 통화와 단위를 먼저 확인합니다. 환율 공급자나 통화쌍을 바꾸면 entity 스키마, Query 키, 변환 계약, 출처 안내와 테스트를 함께 바꿉니다.

단위 검증은 `preferences.test.ts`, `use-formatters.test.tsx`, `resources.test.ts`, `entities/exchange-rate/api/queries.test.ts`가 담당합니다. 실제 화면에서는 언어/통화를 각각 바꾼 뒤 경로 이동·새로고침, 날짜·차트·표·상세 화면, 통화 메뉴 안의 외부 API 실패/재시도, 세 화면 구간의 컨트롤 정렬과 키보드 열기·Escape 초점 복귀를 확인합니다. 실행 범위와 CI 기준은 [테스트 정책](testing.md)을 따릅니다.

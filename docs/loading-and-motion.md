# 로딩·카드 치수·숫자 모션

이 문서가 로딩과 숫자 모션의 단일 계약입니다. 숫자·통화·비율의 표현 옵션은 [숫자 표시](number-formatting.md)가 소유합니다. UI는 기존 shadcn 컴포넌트를 조합하며 커스텀 컨트롤/별도 CSS/모션 라이브러리를 추가하지 않습니다. 캐시 상태 판단은 [Query 캐시](query-cache.md), 일반 정렬은 [레이아웃](design/layout.md)을 따릅니다.

## 카드의 바깥 구조는 유지한다

스켈레톤이 나타나거나 사라져도 **Card의 width/height가 바뀌지 않아야 합니다**. 성공 Card를 대략 비슷한 높이의 Skeleton 하나로 교체하지 않습니다. 같은 Card/Header/Content/Footer, grid 열, padding, gap, border를 유지하고 내용 슬롯만 바꿉니다.

- KPI 레이블/설명/아이콘을 유지하고 `MetricCard`의 같은 수치 프레임을 사용합니다. 모바일은 카드 최소 136px·수치 슬롯 최소 36px, 768px 이상은 카드 최소 192px·수치 슬롯 최소 72px입니다. footer는 공통 최소 32px로 두 줄을 예약합니다. 일반 USD/KRW 샘플의 로딩/성공 치수를 유지하며 예약 영역보다 긴 예외 데이터는 잘리지 않도록 확장합니다. 상세 기준은 [화면 조합](design/compositions.md)과 [긴 콘텐츠](design/content-overflow.md)가 소유합니다.
- 차트는 같은 높이의 프레임 안에서 Skeleton/차트/빈 상태/오류를 전환합니다.
- 표는 열 구성·너비·행 높이·페이지 영역을 예약합니다. 데이터가 적거나 오류가 있어도 바깥 Card가 접히지 않게 고정 viewport 안에 empty/error 콘텐츠를 표시합니다. 초과 데이터는 그 영역에서 스크롤하거나 페이지를 나눕니다.
- footer의 페이지 안내나 긴 설명이 로딩/성공 때 서로 다르게 줄바꿈하지 않도록 같은 responsive grid를 사용합니다.
- 부모만 고정해 내용을 가리면 해결된 것이 아닙니다. 긴 문구·작은 화면·실제 데이터 개수·키보드 초점이 함께 동작해야 합니다. 스크롤/줄 제한을 선택했다면 정보가 필요한 사용자에게 상세 화면이나 접근 가능한 대안을 제공합니다.

`isPending && !data`인 최초 조회에서만 Skeleton을 표시합니다. 캐시 hit와 background refetch는 기존 콘텐츠를 유지합니다. 로딩 화면을 보이게 하려고 캐시를 지우거나 최소 대기 시간을 추가하지 않습니다. Skeleton 장식은 접근성 트리에서 숨기고 Card의 `aria-busy` 또는 하나의 상태 문구로 로딩을 전달합니다.

Skeleton의 pulse도 `prefers-reduced-motion: reduce`에서 중단합니다. 이 처리는 공유 shadcn Skeleton이 소유하며 화면마다 별도 애니메이션을 추가하지 않습니다.

Dialog·메뉴·Sidebar 등의 공간 전환과 spinner의 reduced-motion 구현은 [모션](design/motion.md)을 따릅니다.

### 홈의 최근 활동

홈에서 최근 활동을 처음 불러올 때, 스켈레톤 자리에 실제 항목이 도착하면 본문 전체가 제자리에서 160ms 동안 함께 선명해집니다(불투명도 0.62 → 1, ease-out). 제목·테두리·푸터는 처음부터 제 위치에 표시합니다. 캐시 재방문, 기간·정렬 변경, 백그라운드 재조회에서는 기존 불투명도를 유지합니다. 빈 결과, 오류·재시도와 OS의 동작 줄이기 설정에서는 전환을 생략합니다.

### 프로필 이미지

[공통 프로필 아바타](../src/shared/ui/profile-avatar.tsx)는 사진을 불러오는 동안만 같은 크기의 스켈레톤을 표시합니다. 이미지가 없거나 요청이 실패하면 이니셜을 바로 표시하고, 사용할 이름도 없으면 기본 사용자 모양을 표시합니다. 같은 URL의 데이터를 다시 조회하는 동안 이미 보이는 사진을 가리지 않습니다. 아바타 옆 텍스트나 메뉴 버튼의 접근성 이름이 인물을 설명하므로 장식 이미지를 중복 낭독하지 않습니다.

## 숫자 모션은 선택적으로 300ms 동안 실행한다

`@/features/number-motion`의 `NumberDisplay`는 공통 `formatNumber`로 값을 표시하며 `animate`의 기본값은 `false`입니다. KPI, 요약 금액·비율·개수의 모션은 `animate`를 명시해서 켭니다. 이 경우 API 응답 후 최초 표시와 **캐시로 페이지에 재진입하는 경우 모두** 같은 동작을 사용합니다. 식별자, 날짜, 페이지 번호, 입력값, 모든 표 셀에 모션을 무조건 적용하지 않습니다.

```tsx
<NumberDisplay value={total} format={{ style: 'currency', currency: 'USD' }} animate />
```

- 켠 경우 고정 300ms입니다. frame 개수가 아닌 실제 경과 시간으로 계산하고 deadline에서 최종값을 확정합니다. 숫자 크기에 따라 지속 시간을 늘리지 않으며 호출부에서 duration을 바꾸지 않습니다. 브라우저의 메인 스레드가 멈춘 시간까지 실행을 보장하는 것은 아니며 다시 실행 가능한 즉시 최종값으로 끝냅니다.
- 끈 경우 즉시 최종값을 보여주며 애니메이션 frame이나 deadline timer를 예약하지 않습니다. 실행 도중 꺼도 즉시 최종값으로 끝냅니다.
- 0에서 최종값으로 짧게 이동합니다. 정수 목표는 중간 값도 정수입니다. `format`에는 [공통 숫자 옵션](number-formatting.md)을 전달하고 중간값과 최종값 모두 같은 `formatNumber`를 사용합니다. 통화/비율/축약을 별도 formatter 콜백으로 구현하지 않습니다.
- 최종 문자열과 실제로 표시할 중간 문자열 모두의 너비를 처음부터 예약하고 `tabular-nums`를 사용합니다. 중간 자리수 때문에 옆 아이콘이나 카드가 움직이지 않아야 합니다. `875K → 1M`처럼 중간 문자열이 더 넓어도 잘리거나 마지막에 너비가 줄어들지 않습니다. 공유 컴포넌트는 경과 시간으로 표시 단계를 결정하고 가능한 문자열만 미리 포맷합니다. 같은 형식의 최종값·중간값은 한 번 확보한 공통 formatter를 재사용합니다. 문자열과 전체 폭·높이 예약 요소는 값·형식·줄바꿈 조건이 달라질 때만 다시 계산하며 매 프레임은 이미 준비한 표시 문자열을 선택합니다.
- 목표 값이 바뀌거나 컴포넌트가 새로 나타날 때 실행합니다. 일반적인 부모 rerender나 동일 값 background refresh마다 재시작하지 않습니다.
- `prefers-reduced-motion: reduce`이면 즉시 최종값을 보여 줍니다. 도중에 해당 설정이 켜져도 즉시 끝내고, hidden 문서에서는 불필요한 애니메이션을 완료 처리합니다.
- 화면 낭독기는 정적인 최종값 한 번을 읽습니다. 매 프레임의 숫자를 live region으로 알리지 않습니다. unmount 때 frame·timer·이벤트 구독을 정리합니다.
- `wrap`은 기본 false이며 KPI/좁은 요약에서는 명시해서 켭니다. 최종·중간 문자열에 같은 줄바꿈을 적용해 필요한 높이도 예약합니다. 줄바꿈 변경은 타임라인을 재시작하지 않으며 값·형식·접근 가능한 문자열을 바꾸지 않습니다.

## 확인 기준

production bundle에서 cold load→데이터 표시의 카드 bounding box를 비교합니다. PC/태블릿/모바일에서 너비·높이 차이는 소수점 반올림 오차 0.5px 이내여야 합니다. 카드만 맞고 아래 콘텐츠가 크게 밀리지 않는지도 함께 확인합니다.

숫자 단위 테스트는 정적 기본값, 애니메이션 on/off, 완료 시간, 값 변경, cache 재진입에 해당하는 remount, 일반 rerender, reduced motion, cleanup을 검증합니다. E2E는 네트워크 수와 실제 치수를 확인합니다. 테스트 편의를 위해 동작을 끄거나 검증 범위를 전체 로컬 suite로 늘리지 말고 [테스트 정책](testing.md)을 따릅니다.

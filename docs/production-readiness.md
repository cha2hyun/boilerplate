# 운영 전환 체크리스트

이 보일러플레이트는 앱 구조와 검증 도구를 제공합니다. 실제 서비스의 인증, 권한, 서버, 데이터 운영, 배포 환경까지 완료한 상태는 아닙니다. 아래 항목을 서비스의 요구에 맞게 구현하고 증거를 남긴 뒤 배포하세요.

새 저장소로 복제했다면 먼저 [새 제품 도입 체크리스트](new-project.md)에서 이름·브랜드·저장 namespace·환경·데모 범위를 정리하세요.

## 데이터와 API

- [ ] [API 계약](api-contract.md)에 맞는 서버를 구현하고 `VITE_DATA_SOURCE=api`로 통합 테스트한다.
- [ ] 서버에서 입력 검증, 인증, 리소스별 권한 확인을 수행한다. UI의 표시/숨김을 권한 검사로 사용하지 않는다.
- [ ] 실제 사용자/워크스페이스 식별자를 서버에서 제공한다. 데모 소유자/분석 수치를 실제 데이터로 대체한다.
- [ ] 401/403/404/409/429/5xx, 느린 응답, 오프라인, 취소, 중복 제출을 확인한다.
- [ ] 데이터 증가에 맞춰 서버 검색/정렬/페이지네이션, Query key, 캐시 범위를 결정한다.
- [ ] mutation의 중복 실행/경합/재시도 정책을 정의한다. 금전/비가역 작업에는 서버 idempotency 등을 별도로 설계한다.
- [ ] 저장 구조/마이그레이션/복구 정책을 정의한다. 브라우저 demo 저장소를 운영 데이터베이스로 사용하지 않는다.

## 인증과 환경

- [ ] 세션 수명, 로그아웃, 재인증, 조직 전환과 캐시 삭제 정책을 구현한다.
- [ ] 선택한 인증 방식에 맞는 쿠키 속성/CSRF/CORS 정책을 서버에서 설정한다.
- [ ] 환경별 공개 API 주소를 빌드에 주입한다. `VITE_` 변수, 번들, 저장소, CI 로그에 비밀 값이 없는지 확인한다.
- [ ] CSP, 보안 헤더, 허용 출처, TLS를 배포 플랫폼에서 설정하고 앱과 함께 검증한다.
- [ ] 분석/오류 수집에 개인정보와 자격증명이 포함되지 않도록 필터링한다.

## 배포와 운영

- [ ] 배포할 커밋의 Actions에서 정적/단위/가드레일 검사와 `core`·`samples` 브라우저 범주가 통과한다. 로컬 전체 테스트를 반복하지 않는다.
- [ ] `Conventional PR title` 등 실제 workflow의 상태 이름과 경로 필터를 검토하여 브랜치 보호를 설정한다. 코드 CI는 문서만 바뀌면 생략되므로 무조건 required로 지정하면 pending이 남을 수 있다. [테스트 정책](testing.md)의 경로 필터 설명을 따른다. 현재 파일만으로 원격 설정이 자동 적용되지는 않는다.
- [ ] `VITE_SITE_URL`에 실제 공개 origin을 설정한 `dist/`를 정적 호스팅에 배포한다. 알려진 경로는 해당 디렉터리의 HTML(`projects/index.html` 등)을 먼저 제공하고, 없는 경로는 `404.html`과 HTTP 404를 제공한다. 전역 `/index.html` rewrite로 경로별 OG를 덮어쓰지 않도록 [메타데이터 가이드](seo.md)를 따른다.
- [ ] `/api` 경로는 SPA fallback보다 먼저 API 서버로 연결한다. HTML을 JSON API 응답으로 돌려주지 않는다.
- [ ] 해시 자산은 장기 캐시, HTML은 재검증 정책을 적용하고 이전 릴리스로 롤백하는 절차를 검증한다.
- [ ] 실제 API 연결 상태와 오류율/지연을 관측할 수 있는 운영 지표, 알림, 담당자를 정한다.
- [ ] 의존성 업데이트 PR을 검토하고 lockfile/테스트를 함께 갱신한다. Dependabot은 자동 병합을 설정하지 않는다.

## 사용자 경험

- [ ] 모바일/태블릿/데스크톱, 밝은/어두운 테마를 확인한다.
- [ ] 키보드만으로 탐색/폼/대화상자/표를 조작하고, 화면 낭독기로 이름/오류/초점 이동을 확인한다.
- [ ] 실제 API의 로딩/빈 결과/실패/재시도 상태가 이해 가능하고 동작하는지 확인한다.
- [ ] 샘플 기간, 샘플 계정, 데모 배지를 운영 화면 요구에 맞게 교체한다.
- [ ] 대량 데이터의 렌더링, 번들 크기, 느린 네트워크에서의 성능을 실제 사용 환경에서 측정한다.

배포 방식과 서버 계약이 결정되면 해당 내용을 ADR과 이 체크리스트에 반영하세요. 체크박스는 실제 검증이 끝났을 때만 완료로 표시합니다.

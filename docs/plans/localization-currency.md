# 작업 계획: 저장되는 언어 선택과 실제 환율 기반 통화 전환

상태: 구현 완료 — 로컬 대상 검증 통과, 원격 CI 확인 대기

## 문제와 완료 조건

- 사용자/상황: 한국어와 영어를 전환하고 USD/KRW 금액을 실제 환율에 맞게 비교할 수 있어야 합니다.
- 기존 동작: 영어 UI와 고정 `en-US` formatter, 화면별 USD 표기만 있으며 전체 언어/통화 설정은 없었습니다.
- 변경 후 관찰 가능한 동작: 독립적인 언어/통화 선택이 경로 이동과 새로고침 후 유지되고 UI·aria·날짜·숫자가 선택 언어를 따르며 금액은 공개 API의 USD/KRW 기준 환율로 변환됩니다.
- 제외: 실제 결제/정산, 실시간 체결가, 사용자 콘텐츠 자동 번역, 추가 통화, RTL, 인증/백엔드 구현.

## 확인한 근거

- 소유 코드: `shared/lib/i18n`, `entities/exchange-rate`, 앱 provider, `features/number-motion`, 화면/공통 UI.
- 원본 단위: Overview KPI/차트는 USD 주요 단위, Orders/Customers는 USD cents. 후자는 표시 직전에 `/ 100`이 필요합니다.
- 공급자: [Frankfurter v2](https://frankfurter.dev/) 단일 통화쌍 공개 API. 2026-11-04 실제 응답과 CORS를 작업 중 확인했으며 관측값을 고정 환율로 저장하지 않습니다.
- 영어 UI 문자열을 기본값으로 보존하고 샘플 고유명사·사용자 입력·메시지 본문은 유지합니다.
- 병렬 작업은 소유 파일을 나누고 공통 formatter API로 연결합니다. 공급자·저장 계약은 한 곳에서 관리합니다.

## 변경 경계

- `shared`: 타입이 있는 번역 리소스, 검증된 언어/통화 환경 설정, locale formatter와 변환 함수, 주입용 환율 context.
- `entities/exchange-rate`: 공개 HTTP 응답 검증, 키와 6시간/24시간 Query 캐시, 취소/오류 처리.
- `app`: i18next·문서 언어·Query provider 조립, 라우트/시작/메타데이터의 언어 반영.
- `features/widgets/pages`: 기존 shadcn 컨트롤로 설정과 상태 안내, 번역 문구, 지역별 숫자와 금액 표시.
- 저장: 새 `blueprint-locale-preferences` 버전 1. 기존 도메인 데이터는 변경하지 않으며 환율은 영구 저장하지 않습니다.
- 실패: 유효한 환율이 없으면 KRW `—`, 캐시가 있으면 마지막 정상 응답 유지. USD는 환율 없이 표시합니다. 오류·재시도는 번역하고 실제 실패를 샘플 환율로 대체하지 않습니다.
- 자세한 공개 계약은 [언어와 표시 통화](../i18n.md)를 따릅니다.

## 실행과 검증

1. 번역/저장/환율/formatter와 화면 연동을 구현하고 영어 기본 문자열을 보존합니다.
2. 단위 테스트로 응답 통화쌍·날짜·유한 양수, Query 중복 제거/수명/실패/취소, 저장 복원·오염 값, 언어/통화 독립성, 실제 배율 변환·cents 경계, 리소스 parity를 확인합니다.
3. 로컬 정적 검사 `pnpm check`와 변경 범위의 필요한 최소 테스트를 수행합니다. 전체 로컬 테스트/빌드는 기본 절차로 추가하지 않습니다.
4. production 번들의 좁은 E2E/브라우저 범위에서 한국어·영어, USD·KRW, 새로고침 보존, 표/차트/상세 금액, 실패/재시도, 세 화면 구간과 키보드를 확인합니다. 외부 응답 fixture는 테스트에만 둡니다.
5. 소유 문서의 미구현 설명을 현재 계약으로 바꾸고 관련 Actions 결과를 확인합니다.

## 완료 기록

- `pnpm check`의 포맷/ESLint/타입/FSD 검사를 통과했습니다.
- 환율, 언어·통화 저장, formatter, 리소스 일치, 메타데이터, HTTP client, 숫자 모션의 7개 파일 93개 대상 테스트를 통과했습니다. 전체 로컬 테스트/빌드는 실행하지 않았습니다.
- 실제 Chrome에서 공개 API 응답을 사용해 한국어·원화 전환, 기준일·환산 금액·제목 반영, 데스크톱/모바일 컨트롤 정렬과 가로 넘침을 확인했습니다. 브라우저 오류는 없었습니다.
- Astra 6 xhigh의 최종 소스 리뷰는 96/100이며 남은 P1/P2 지적은 없었습니다. 이 평가는 자동 테스트/운영 검증을 대신하지 않습니다.
- 전체 단위·production 번들·세 화면 구간 E2E는 원격 CI에서 확인합니다. 이 기록만으로 최종 CI 성공을 주장하지 않으며 PR/작업 완료 기록의 실행 링크와 최종 SHA를 확인합니다.
- 남은 제약: 외부 API의 일별 기준 환율과 네트워크 가용성에 의존하며 기존 업무 데이터는 계속 샘플입니다.

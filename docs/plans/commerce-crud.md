# 작업 계획: 주문·고객 테이블 생성·수정·삭제

상태: 구현 완료 · CI 검증 연계

## 문제와 완료 조건

- 프로젝트에는 편집 흐름이 있지만 주문·고객 테이블은 조회 전용입니다.
- 주문·고객에 생성/편집 Dialog와 삭제 AlertDialog를 연결하고 HTTP mutation 결과가 표·요약·열린 상세에 반영되어야 합니다.
- 데모 변경은 검증된 브라우저 저장소로 복원하며, 저장소 사용이 불가능하면 현재 세션에서 유지합니다.
- Zod 검증, 중복 제출 방지, 미저장 입력 보호, 실패 시 입력 유지, 초점 복귀와 세 화면 구간을 지원합니다.
- Analytics의 집계 표와 Components의 설명용 표는 편집 대상이 아닙니다. 실제 결제·배송·고객 계정/메일·인증 서버를 추가하지 않습니다.

## 확인한 근거

- `entities/project`와 `features/project-editor`에 검증·저장·캐시·입력 보호의 기존 예제가 있습니다.
- `entities/order`, `entities/customer`는 목록 HTTP Query를 사용하며 `app/mocks/handlers.ts`가 MSW 응답을 소유합니다.
- 주문의 고객 정보는 스냅샷이고 고객 구매 합계는 독립 샘플입니다. 고객 삭제/수정으로 주문을 연쇄 수정하거나 구매 집계를 만들어내지 않습니다.

## 변경 경계

- 각 entity는 입력/응답 스키마, HTTP mutation, 데모 저장 어댑터와 계약 테스트를 소유합니다.
- 각 editor feature는 기존 shadcn Dialog/AlertDialog, 입력 보호, 번역된 검증/오류를 조합합니다. pages는 생성 버튼·행 메뉴·선택/초점을 연결합니다.
- app/mocks는 GET/POST/PATCH/DELETE를 명시적으로 처리합니다. 실제 API 모드에서는 같은 경로를 실제 서버로 보냅니다.
- 금액 원본은 USD cents를 유지합니다. 주문 폼의 입력 단위는 USD로 명시하고 고객 주문/누적 금액 필드는 편집하지 않습니다.
- Query 성공 시 진행 중 조회를 취소하고 동일 목록 캐시를 갱신/재검증합니다. 불확실한 write 결과는 재조회하며 자동 재전송하지 않습니다.
- 신규 버전 저장 키를 사용하므로 기존 프로젝트/환경 설정 저장 형식을 바꾸지 않습니다.

## 실행과 검증

1. 주문·고객 슬라이스를 독립적으로 구현하고 공통 mock HTTP/번역 등록을 통합합니다.
2. 입력 경계·저장 복원·없는 대상·mutation 캐시를 단위 테스트로 확인합니다. 기존 commerce E2E에 CRUD·새로고침 지속성·입력 보호를 연결합니다.
3. 로컬 기본은 `pnpm check`이며 전체 테스트와 production build는 Actions에서 실행합니다.
4. 필요한 결함 재현만 해당 파일·동작·화면 크기로 제한합니다.
5. 페이지 기획, API/Query/데이터 모드, README의 조회 전용 설명을 갱신합니다.

## 완료 기록

- 주문·고객 HTTP CRUD, 검증된 버전 저장소, 캐시 갱신, Dialog/AlertDialog와 행 메뉴를 연결했습니다. 프로젝트의 기존 CRUD는 유지합니다.
- 생성 후 필터를 유지하며 새 항목 상세를 엽니다. 미저장/요청 중 보호, 키보드 메뉴 초점, 삭제 뒤 페이지 보정, 새 고객의 구매 이력 구분을 반영했습니다.
- 스키마·USD 변환·저장 복원·HTTP·캐시 경합·폼 입력 보호와 기존 commerce E2E에 CRUD/응답 손실 시나리오를 추가했습니다.
- 로컬 전체 테스트·빌드는 실행하지 않았습니다. 정적 검사는 `pnpm check`, 전체 단위·가드레일·production build와 세 화면 브라우저 실행 결과는 이 변경 PR/최종 main의 Actions가 기록합니다.
- 주문·고객 기획과 API·캐시·입력 보호·공통 조합 문서를 현행화했습니다. 새로운 패키지나 테스트 job은 추가하지 않았습니다.

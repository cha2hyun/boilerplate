# 작업 계획: 입력 보호와 앱 오류 복구

상태: 구현 완료 · 최종 CI 결과는 이 변경을 포함한 PR의 검사 기록에서 확인

## 문제와 완료 조건

- 설정과 프로젝트 폼의 미저장 입력이 페이지 이동·닫기·새로고침으로 사라질 수 있다. 변경이 있을 때만 이탈 의사를 확인하고 계속 편집을 선택하면 입력과 초점을 유지한다.
- 페이지 오류 UI 밖의 Provider 렌더 오류와 전역 실행 오류에 대한 공통 보고 연결점이 없다. 앱 전체 복구 화면과 개인정보를 포함하지 않는 오류 보고 계약을 제공한다.
- 기존 shadcn, 번역, FSD, 저장·mutation 계약을 유지하고 실제 외부 수집 서비스를 연결했다고 설명하지 않는다.
- 범위 제외: 포크 초기화 자동화, 실제 인증/백엔드/관측 서비스, 새 의존성, Router에 이미 있는 chunk 재로드 중복 구현.

## 확인한 근거

- 시작 main `18a5e73`, Actions 성공, 열린 Dependabot PR·보안 알림 없음.
- Settings의 dirty 상태는 저장 버튼만 제어한다. ProjectEditorDialog는 저장 중 닫기만 막는다.
- Router의 route error UI와 demo startup 화면은 있으나 앱 Provider 전체 경계와 오류 보고 adapter는 없다.
- TanStack Router 탐색 차단과 React root 오류 콜백을 설치된 버전·공식 문서 기준으로 확인한다.

## 변경 경계

- shared는 도메인과 무관한 입력 보호/보고 계약, app은 root·Router·전역 이벤트 연결을 소유한다.
- Settings와 ProjectEditor는 실제 dirty·pending·저장 성공 여부를 소유한다. 입력을 저장소에 자동 보관하지 않는다.
- 앱 내 확인은 shadcn AlertDialog, 탭 닫기·새로고침은 브라우저 기본 확인을 사용한다. 브라우저의 표시 제한을 문서화한다.
- 오류의 원문·stack·URL·사용자 입력을 기본 보고 payload에 넣지 않는다. 중복 보고·보고 adapter의 실패가 앱에 전파되지 않게 한다.
- UI 변경과 관련된 페이지 기획·디자인 계약을 갱신하고 기존 core/samples CI 범주와 production bundle을 재사용한다.

## 실행과 검증

1. 입력 보호와 오류 복구/보고를 병렬 구현한다.
2. 단위 계약과 사용자 이탈 흐름 E2E를 추가하고 기존 테스트에 바뀐 UX를 반영한다.
3. 로컬 정적 검사와 필요한 선택 테스트만 수행한다. 전체 테스트·빌드는 Actions에서 실행한다.
4. 독립 리뷰, 커밋·푸시·PR, 최신 main Actions 성공을 확인한다.

## 완료 기록

- Settings와 ProjectEditor에 공통 미저장 입력 확인을 적용했다. 저장 중 보호, 성공/원복 후 해제, 계속 편집 초점, 숨겨진 일반 탭, 중복 이동과 미해결 확인 정리를 포함한다.
- Provider 밖의 앱 복구 화면, 초기화 실패 즉시 처리, React/route/전역 보고 연결과 개발·운영 진단을 구현했다. 기본 외부 전송은 없으며 실제 관측 서비스 연결은 제품 작업이다.
- 보고 payload는 고정 필드만 사용하고 원문·stack·URL·사용자 값을 제외한다. 같은 오류의 중복, adapter throw/reject/재귀를 처리하며 느린 비동기 전송이 다른 오류를 막지 않는다.
- `pnpm check`와 필요한 선택 테스트 52개가 통과했다. 전체 로컬 테스트·브라우저·빌드는 실행하지 않았다.
- production E2E에 입력 폐기·계속 편집·history·native reload와 Provider 실패 후 재진입을 추가했다. 기존 core 범주·두 job·공유 production build를 유지한다.
- Astra xhigh 독립 리뷰의 React 진단 누락을 수정했고, 초기화 대기와 비동기 보고 차단 문제도 보강했다. 최종 원격 검증은 PR과 최신 main Actions의 실제 결과를 기준으로 한다.
- 브라우저가 종료 경고를 생략하거나 모바일 앱이 강제 종료되는 경우까지 초안을 보존하지 않는다. 오류 경계는 번들 평가 이전 또는 복구 화면 자체의 실패까지 복구하지 않는다. 세부 범위는 입력 보호·오류 처리 소유 문서에 기록했다.

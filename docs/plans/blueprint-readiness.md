# 작업 계획: 관리자 blueprint의 접근성·재사용·검증 완성도

상태: 구현 완료. 브라우저 회귀와 빌드 결과는 각 커밋의 PR Checks에서 확인한다.

## 문제와 완료 조건

- 사용자/상황: 2026-11-06의 종합 평가 후 개선 실행을 승인했다.
- 현재 동작: 공통 입력 대비와 heading 구조, 모바일 목록 문맥·확대 안내에 빈틈이 있다. Orders는 전체 배열 기반이며 공개 origin과 색인 정책이 결합돼 있다. CI 브라우저 설치 지연과 일부 검사 예외도 남아 있다.
- 변경 후 관찰 가능한 동작: 접근성·모바일 문제를 해결하고, Orders에 검증된 서버 조회·상세·요약 계약을 제공한다. 관리자 색인을 기본 차단하고 최소 제품 도입 경로와 저장 지속성 안내를 명확히 한다. 번들 예산·가드레일·CI 실행 환경이 변경을 보호한다.
- 범위에서 제외하는 항목: 실제 인증·권한·결제·백엔드·외부 오류 수집 서비스와 배포. 하위 경로 호스팅과 번역 지연 적재는 실제 도입/측정 요구 없이 확장하지 않는다.

## 확인한 근거

- 기준: 깨끗한 main `539d38b`. 평가 중 해당 CI production artifact에서 화면과 실제 대비를 확인했다.
- 관련 파일/테스트/API 계약: `docs/design/accessibility.md`, `docs/api-contract.md`, `docs/query-cache.md`, `docs/testing.md`, `docs/seo.md`, 페이지별 명세와 대응 소유 코드.
- 가정과 아직 확인할 점: 화면낭독기·실기기·실제 운영 API 검증을 자동 브라우저 검증으로 대체하지 않는다. 새로운 CI 실패와 Dependabot PR은 현재 원격 근거로 다시 확인한다.
- 기존 변경과 충돌 가능성: 작업 시작 시 사용자 변경 없음. UI, Orders 데이터 계약, 하네스, 메타/도입/저장 안내를 분리해 병렬 작업한다.

## 변경 경계

- 영향 레이어/슬라이스: 공통 UI/토큰, app 메타·복구, 프로젝트/고객 목록, 주문 entity/feature/page, MSW, 공통 저장 상태, 문서·검사 스크립트·Actions.
- 공개 API/환경 변수/저장 형식 변경: Orders의 목록 응답과 상세·요약 API를 명시적으로 갱신한다. 기존 브라우저 주문 데이터는 보존한다. 공개 origin은 색인 허용과 분리한다.
- 오류/빈 상태/취소/접근성 처리: 기존 오류 복구·미저장 보호·불확실한 쓰기 재조회·URL 복원을 유지한다. 저장소 실패는 세션 유지 상태를 알린다.
- 마이그레이션/롤백: 운영 서버는 미구현이다. 새 API 계약을 연결할 서버는 문서와 함께 갱신해야 한다. 기존 저장 namespace와 스키마를 보존한다.

## 실행과 검증

1. 최소 구현: UI 대비/heading/모바일, Orders 대표 계약, 관리자 메타 기본값/최소 도입, 지속성 안내, 하네스·CI를 책임별로 구현한다.
2. 필요한 계약/행동 테스트와 CI 범주: 기존 foundations/data/ui 및 core/samples 범주를 유지하고 실제 결함/계약에 필요한 회귀를 추가한다.
3. 로컬 정적 검사 `pnpm check`: 통합 후 실행하고 변경 범위별 커밋·푸시한다.
4. 꼭 필요한 로컬 재현만 선택: 검사기·특정 계약 테스트를 좁혀 실행한다. 전체 단위/E2E/build는 Actions에서 실행하고 해당 production artifact로 화면을 확인한다.
5. 문서/운영 체크리스트 반영: 페이지 명세, API/캐시, 접근성·국제화, SEO·도입, 테스트/가드레일·의존성 정책을 실제 구현과 맞춘다.

## 완료 기록

- 실제 변경 동작: 대비·제목·확대·모바일 목록, 페이지 단위 Orders 조회·상세·집계, 세션 전용 저장 안내, 기본 noindex와 최소 포크 예시를 구현했다. CI는 고정 브라우저 이미지, 초기 JS 예산, 파일별 UI 예외, 예상 밖 브라우저 오류 및 문서 링크를 검사한다.
- 집중 확인: 저장·메타데이터·주문 API/경합·하네스 검사와 frozen 설치, 통합 `pnpm check`를 통과했다. 전체 앱 테스트/빌드는 로컬에서 반복하지 않는다.
- 원격 근거: 기존 [main CI](https://github.com/cha2hyun/boilerplate/actions/runs/42061487415)는 중단됐던 core를 재실행해 quality/core/samples와 CI Gate가 모두 성공했다. 이번 변경의 완료 판정은 별개의 최신 PR head에서 quality/core/samples와 CI Gate 결과로 한다. 이미지 변경은 Linux actual/diff를 검토해 반영한다.
- 남은 제약: 실제 인증/권한/서버·운영 모니터링은 제품별 연결 대상이다.

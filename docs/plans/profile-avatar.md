# 작업 계획: 로그인 계정과 공통 프로필 이미지

## 문제와 완료 조건

로그인한 사용자가 헤더에서 자신을 알아볼 수 있어야 한다. 모바일·태블릿은 사진만, PC는 닉네임도 보여 주고, 실패하거나 느린 이미지도 메뉴의 크기와 동작을 유지한다. 샘플 계정의 이름은 soohyun, 성은 chae다.

## 변경 경계

[헤더](../design/layout.md#앱-헤더-오른쪽-아이콘)·[계정](../pages/account.md)·[사용자](../pages/users.md)가 공통 [이미지 로딩](../loading-and-motion.md#프로필-이미지) 계약을 사용한다. Query가 가진 실제 이름·사진 주소를 표시하고, 사진이 없는 기록은 이니셜로 나타낸다. 구성원 저장 키와 계정 ID는 유지한다. 기존 데모 소유자 정보만 갱신하고 다른 구성원과 초대 기록을 보존한다.

## 실행과 검증

- 이미지 성공·지연·실패·주소 변경, 기존 저장 데이터 마이그레이션을 집중 검사한다.
- 모바일·태블릿·PC에서 계정 트리거의 크기·닉네임·키보드 동작을 확인한다. 일반 헤더 아이콘 규칙은 그대로 검사한다.
- 로컬 `pnpm check`와 변경 범위의 단위·브라우저 검사로 검증한다.

## 완료 기록

기존 v1 소유자와 초대 사용자가 함께 있는 브라우저 저장 상태로 로그인해, 내 계정에 `soohyun`·`chae`가 표시되고 초대 사용자의 역할·상태가 보존되는 것을 확인했다. 390px WebKit에서는 계정 버튼이 32×32px이고, 1440px에서는 같은 높이에서 닉네임까지 표시했다. 지연·오류·주소 변경과 헤더 접근성은 [공통 아바타 단위 검사](../../src/shared/ui/profile-avatar.test.tsx)와 [계정 브라우저 검사](../../e2e/workspace-users.spec.ts)에서 검증한다.

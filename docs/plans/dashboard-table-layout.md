# 작업 기록: 대시보드 밀도와 넓은 주문 표

상태: 구현 완료 · 후속 원격 검증은 [PR #18](https://github.com/cha2hyun/boilerplate/pull/18)에서 추적

> 아래 보류·미실행 기록은 각 기능 구현 당시의 결과입니다. 2026-11-04 후속 요청으로 Actions와 main 병합 절차를 재개했습니다. 최신 검증 결과와 최종 SHA는 연결된 PR에서 확인합니다.

## 문제와 완료 조건

- 헤더의 Demo workspace 표시를 제거합니다.
- 최근 활동의 과도한 항목 간격 때문에 매출 카드가 늘어나지 않아야 합니다.
- 주문 표는 필드를 숨기지 않고 작은 화면에서도 가로로 탐색할 수 있어야 합니다.
- 로딩·성공·빈 결과에서 표의 높이를 유지하며 터치·키보드 탐색을 보존합니다.

## 변경 경계

- AppShell의 데모 배지와 사용하지 않는 번역 키를 제거했습니다.
- Overview는 카드의 시작점을 맞추고 RevenueChart의 강제 전체 높이를 제거했습니다. 최근 활동은 352px 영역에서 기본 네 항목을 보여주며 긴 문구는 잘라내지 않고 세로 스크롤로 접근합니다.
- Orders는 기존 API 데이터로 12개 열을 구성합니다. 최소 폭은 1840px, 표 프레임은 496px이며 첫 주문번호 열을 고정했습니다. 데이터·캐시 키·저장 계약은 바뀌지 않습니다.
- shadcn Table의 기존 스크롤 요소에 `containerProps`로 이름·설명·키보드 초점·로딩 상태를 전달합니다. 터치는 브라우저의 네이티브 스크롤을 사용합니다.
- 사용자 추가 요청인 전역 스크롤바와 고정 gutter 규칙은 [스크롤](../design/scrolling.md)에 기록합니다.

## 검증 기록

- 데스크톱 1440px에서 매출 카드 높이 479px, footer 아래 여백 25px을 확인했습니다. 최근 활동의 네 항목은 각각 76px로 352px 영역 안에 표시됩니다.
- 1440/834/390px 화면에서 페이지 전체의 가로 넘침이 없고, 주문 표 내부에만 가로 넘침이 있는 것을 확인했습니다.
- 브라우저의 가로 휠과 오른쪽 화살표로 표 이동, 주문번호 고정 및 마지막 합계 열 접근을 확인했습니다.
- 기존 workspace/commerce E2E에 차트 하단 공간, 활동 접근, 12열 구조, 키보드 및 Chromium 실제 양방향 터치 제스처 회귀 검사를 추가했습니다.
- 사용자 지시에 따라 전체 로컬 테스트·빌드·Actions·PR·main 머지는 실행하지 않습니다. 실제 터치 제스처 E2E는 작성했으며 실행 결과로 보고하지 않습니다.
- 최종 `pnpm check`가 통과했습니다: Prettier·ESLint·TypeScript·아키텍처·E2E 범주 검사. 전체 테스트·번들 빌드는 포함하지 않습니다.
- 전역 스크롤바는 light/dark에서 확인했습니다. Chrome의 overlay 환경에서 긴 주문 → 짧은 설정 이동 전후 header 가로 위치/너비가 256px/1176px로 같았고, 모바일 390px에서도 모달 전후 0px/390px를 유지했습니다. 일반 스크롤바 환경의 E2E는 실행 보류 상태입니다.

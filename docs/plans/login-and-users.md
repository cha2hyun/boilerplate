# 작업 계획: 로그인과 워크스페이스 사용자 샘플

## 문제와 완료 조건

고객 구매 기록과 별개로 내부 사용자가 로그인해 자기 계정을 보고 구성원을 관리하는 예시가 필요하다. 기존 페이지는 공개 데모로 둘러보고, 사용자·내 계정에 바로 들어오면 공개 샘플 계정으로 로그인한 뒤 원래 화면과 조회 조건으로 돌아간다.

## 변경 경계

- 탭 세션에는 고정된 샘플 사용자 식별자만 남긴다. 로그인 입력을 보내거나 저장하지 않는다. 이 흐름은 데모 모드에서만 사용하며 실제 서버의 인증·권한 검사를 대신하지 않는다.
- 구성원은 고객과 별도의 스키마, HTTP 경로, Query 키, 저장 키를 사용한다. 초대는 대기 상태 레코드를 생성한다. 구성원 역할·상태 변경과 본인 보호는 MSW 데모 어댑터에서도 검증한다.
- 라우트는 로그인 복귀 위치와 사용자 목록 조회·상세, Query는 사용자 데이터, 로그인 폼·초대/수정창은 초안을 소유한다. 새 저장 키만 추가한다.

## 구현과 검증

- 로그인·언어 전환, 탭 세션·종료, 안전한 복귀 목적지, 내 계정과 사용자 검색·상세·초대·수정·실패 처리를 연결한다. 홈페이지에서 데모를 둘러보는 기존 진입점을 유지한다.
- 페이지 명세와 API·SEO·도입 문서를 갱신한다. 로컬은 정적 검사와 새 계약의 집중 검증, 전체 단위·빌드·세 화면 구간 E2E는 PR Actions에서 확인한다.
- 작업 기준은 사용자에게 제공 중인 PR #42의 `7cf87ff`. 후속 PR은 이 브랜치에 쌓아 로그인 기능의 diff를 따로 검토할 수 있게 한다.

## 완료 기록

- 사용자·내 계정 직접 진입, 검색/상세 복귀, 공개 계정 로그인과 탭 종료, 초대·역할 수정·본인 보호를 구현했다. 운영 API 모드에서 저장된 샘플 ID만으로 구성원 API 요청이 발생하지 않는 것도 확인했다.
- `pnpm check`와 세션·반환 URL·데이터 어댑터·편집 폼 계약 검사를 실행했다. LAN 브라우저에서는 한국어 모바일 화면, 초대 기록 저장·수정, 미저장 설정에서 로그아웃 취소를 확인했다.
- 실제 Chrome이 로그아웃 이전의 사용자·내 계정 문서를 캐시에서 복원해도 샘플 데이터가 사라지고 로그인으로 돌아옴을 확인했다. 해당 복원 이벤트의 회귀 검사도 포함한다.
- 전체 빌드·가드레일·브라우저 결과는 [후속 PR의 검사](https://github.com/cha2hyun/boilerplate/pull/43/checks)에서 변경 커밋별로 확인한다. 제품별 서버 인증·권한·메일 발송은 별도의 연결 대상이다.

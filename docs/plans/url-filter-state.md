# 작업 계획: URL로 조회 조건 복원

상태: 구현·로컬 검증 완료

## 문제와 완료 조건

- 차트 기간과 테이블 필터가 컴포넌트 상태에 있어 새로고침·다른 페이지 방문 뒤 돌아오면 초기화됩니다.
- Overview, Projects, Analytics, Orders, Customers, Inbox의 조회 조건을 URL에 저장합니다.
- 직접 링크·새로고침·뒤로/앞으로 이동에서 검증된 조건과 화면이 일치해야 합니다.
- 잘못된 필드만 Zod 기본값으로 복구하며 정상적인 다른 필드는 유지합니다.
- 대화상자, 행 선택, Inbox 샘플 데이터 변경과 컴포넌트 데모의 임시 조작은 대상에서 제외합니다.

## 확인한 근거

- 기존 라우트는 검색 파라미터 검증이 없고 각 페이지/위젯이 useState로 조건을 소유합니다.
- TanStack Router와 Zod 4가 이미 설치되어 있어 추가 어댑터 의존성이 필요하지 않습니다.
- 프로젝트 표는 Overview와 Projects에서 함께 사용하므로 제어 상태를 props로 주입합니다.

## 변경 경계

- app 라우트는 validateSearch와 탐색을, pages/widgets 모델은 조회 스키마를 소유합니다.
- Router 상태를 페이지/위젯에 전달하며 Query 결과와 Zustand에 복제하지 않습니다.
- 기존 UI와 Query 키·어댑터는 유지합니다. 필터 변경은 페이지 1로 이동하고 로딩 중 페이지를 임의로 초기화하지 않습니다.
- 검색 입력은 history replace, 선택·정렬·페이지 이동은 push를 사용하고 필터 변경 시 스크롤을 유지합니다.

## 실행과 검증

1. 공통 입력 경계와 화면별 스키마·제어 컴포넌트를 구현합니다.
2. Zod 경계 테스트와 기존 E2E의 URL·새로고침·뒤로/앞으로 복원 검증을 보완합니다.
3. pnpm check와 관련 범위 테스트만 로컬에서 실행합니다. 전체 테스트·빌드는 Actions에 맡깁니다.
4. 조회 상태 규칙과 문서 지도를 갱신하고 기능 커밋·푸시 후 CI를 확인합니다.

## 완료 기록

- 여섯 화면의 조회 조건을 Zod 검증된 Router search로 연결했습니다. 필드별 복구·기본값 생략·조회 성공 후 페이지 보정과 검색 입력 replace 정책을 적용했습니다.
- Inbox는 URL 조건 변경 시 임시 상세 선택만 해제하고, 읽음/보관 샘플 변경은 기존 로컬 상태로 유지합니다.
- `pnpm check`, 관련 단위 테스트 47건, `git diff --check`가 통과했습니다. 독립 리뷰에서 발견한 기간 직렬화 assertion과 캐시 갱신 중 페이지 보정 문제를 수정했습니다.
- 기존 production E2E에 새로고침·뒤로/앞으로·직접 링크·잘못된 파라미터·캐시 재사용 검증을 추가했습니다. 전체 로컬 테스트·빌드·브라우저 검사는 실행하지 않았습니다.
- 원격 실행 결과는 해당 기능 PR의 최신 head Actions에서 확인합니다. 이전 main의 문서 CI가 GitHub queued 상태였으므로 새 실행의 성공을 별도로 확인해야 합니다.

# 작업 계획: 관리자 blueprint의 업무 흐름과 검증 공백 개선

상태: 구현 완료. 최신 원격 통합 검증은 [PR #37의 checks](https://github.com/cha2hyun/boilerplate/pull/37/checks)를 기준으로 한다.

## 문제와 완료 조건

- 사용자/상황: 관리자 프런트엔드 blueprint 전반 평가에서 확인한 결함과 도입·업무·검증 공백을 개선한다.
- 현재 동작: 다크 차트의 축 색상이 적용되지 않고, 워크스페이스 이름 설정이 화면에 반영되지 않는다. 쓰기 HTTP 5xx의 결과 불확실성과 응답 순서·식별자 계약에 공백이 있다. 주문 작업이 넓은 표의 끝에 있고 상세 URL을 공유할 수 없다.
- 변경 후 관찰 가능한 동작: 실제 차트 대비와 설정 결과를 검증하고, 불확실한 쓰기는 재확인한다. 날짜/ID 경계를 검증하며 목록·상세·수정 동선을 줄인다. 에이전트 검사기의 오탐·누락과 오류 상태 회귀를 보강하고 새 제품 도입 안내/이미지를 현재 구현에 맞춘다.
- 범위에서 제외하는 항목: 실제 백엔드·인증·권한·결제·운영 감사 시스템의 신규 구현과 배포. 데모의 기록/상태 흐름은 실제 운영 기능으로 설명하지 않는다.

## 확인한 근거

- 관련 파일/테스트/API 계약: 평가 기준 main `8b2b6d8`; `shared/ui/chart`, `widgets/app-shell`, `shared/api/client`, `entities/*`, Orders/Customers 화면·URL, `scripts/check-architecture`, `e2e`, 관련 페이지 명세와 디자인 계약.
- 가정과 아직 확인할 점: 실제 운영 데이터 규모와 인증/서버 정책은 정해지지 않았다. 현재 Lighthouse 수치는 폰트 CDN 전환 이전이며 변경 후 대표 환경을 다시 측정한다.
- 기존 변경과 충돌 가능성: 시작 시 작업 트리는 깨끗했다. Astra xhigh 세 담당이 파일 소유권을 나누고 root가 공통 파일·통합·커밋을 관리한다.

## 변경 경계

- 영향 레이어/슬라이스: app, pages/orders·customers·overview·projects, widgets/app-shell·project-table, entities, shared UI/config/API, 검사 스크립트와 CI.
- 공개 API/환경 변수/저장 형식 변경: 목록 응답 유일성·Traffic 정규화·불확실성 처리 강화. 기존 저장 키 값은 보존하고 구성 위치를 정리한다. 상세 ID/페이지 크기는 검증된 URL 상태로 추가한다. 주문에는 상태·결제 변경 이력 최대 100개를 추가하며 이전 데이터의 누락 이력은 빈 배열로 해석한다. 사용자·기기 간 동기화나 신뢰할 수 있는 운영 감사 이력은 아니다.
- 오류/빈 상태/취소/접근성 처리: 결과가 불확실한 저장 재조회, 없는 상세 ID 복구, 키보드/초점 복원, 모바일 요약 접기, 실제 차트 텍스트 대비, cold/stale/empty 응답 회귀를 포함한다.
- 마이그레이션/롤백 (필요할 때): 저장 키 값은 바꾸지 않는다. 새로운 저장 필드는 이전 저장 데이터를 검증·복원할 수 있게 설계하며 데이터 삭제로 전환하지 않는다.

## 실행과 검증

1. 최소 구현: 데이터 계약, 업무 화면, 하네스/CI를 병렬 구현하고 root가 차트·셸·도입 경험과 통합을 담당한다.
2. 필요한 계약/행동 테스트와 CI 범주: 각 소유 단위 테스트와 기존 core/samples E2E에 회귀를 추가한다. 테스트 범주 누락은 허용하지 않는다.
3. 로컬 정적 검사 `pnpm check`: 통합된 변경에서 수행한다. 전체 테스트·빌드는 Actions를 기본으로 한다.
4. 꼭 필요한 로컬 재현만 선택 (파일/동작/화면 크기, production 번들): 검사기/응답 결함은 좁은 테스트, UI는 CI production artifact에서 대표 화면과 오류·초점 상태를 확인한다. 시각 기준 변경은 Linux 실제 결과를 확인한 뒤 승인한다.
5. 문서/운영 체크리스트 반영: 페이지 목적/행동/상태와 검증 근거를 함께 갱신한다. 실제 운영 범위와 데모를 구분한다.

## 완료 기록

- 실제 변경 동작: 차트 축 대비, 워크스페이스 이름 표시, 제품/저장 키 중앙화, 쓰기 5xx 재확인, 응답 날짜/ID 검증, 주문 변경 기록, 상세 URL/페이지 크기, 모바일 요약 접기, 표/페이지 책임 분리, guardrail const/spread 처리와 오류/빈 상태·WebKit 회귀를 구현했다.
- 실행한 명령과 결과: 시작 원격 main CI 성공, 열린 Dependabot PR/보안 알림 0건. 통합 `pnpm check` 통과. 담당별 결함 재현용 선택 테스트·ESLint 통과. `2ba2bb6` production 번들의 대표 화면 6개에서 페이지 가로 넘침·실행 오류 0건을 확인하고 소개 이미지 4개를 갱신했다. 최신 Lighthouse와 이전 main의 같은 runner 비교는 [실측 기록](../reviews/lighthouse-audit.md)에 남겼다.
- Actions 실행 결과 또는 미실행 사유 (로컬 전체 테스트는 기본 절차가 아님): `01716fb` CI에서 전체 단위 489개·guardrail 82개 통과. 후속 `2ba2bb6`의 quality와 samples 50개가 통과했으며, core의 의도된 Orders 시각 차이는 Linux actual을 검토해 기준 이미지로 반영했다. 모바일 hidden 카드의 잘못된 치수 수집은 수정 후 동일 production artifact의 해당 2개 테스트에서 통과했다. 최종 이미지 반영 후 CI 성공 여부와 병합 SHA 검증은 PR의 최신 checks와 완료 보고에 연결한다.
- 남은 제약: 실제 API·인증·권한·운영 배포와 서버 페이지네이션은 별도 제품 계약이 필요하다. WebKit smoke는 실제 iPhone/Safari 검증을 대신하지 않는다. 모바일 메인 스레드 비용은 Lighthouse의 단일 실험실 결과로 남기며 성능 개선을 과장하지 않는다.

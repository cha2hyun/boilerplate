# 작업 계획: 통화 메뉴 정리와 starter 재사용성 검토

상태: 구현·로컬 검증 완료. 원격 완료 근거는 이 변경 PR과 최종 main SHA의 Actions 기록을 따른다.

## 문제와 완료 조건

- 통화 메뉴에서 설명 문단과 날짜를 제거하고 Lucide Banknote로 표시 통화를 구분한다.
- Astra 6 xhigh 세 리뷰어가 구조/데이터, UX, 하네스/도입을 독립 검토한다. 실제 코드로 확인한 결함과 제품별 추가 구현을 구분해 점수를 기록한다.
- 확인된 API 쓰기 결과 불확실성, offset 날짜 정렬, 최근 매출 기간 계산, 초기 목록 오류 안내를 수정한다. 반응형/차트 후보는 브라우저 재현 후 반영한다.
- E2E 범주 누락을 정적으로 차단하고 새 제품 도입 절차를 연결한다.
- 인증·권한·실제 백엔드·오류 수집 업체 도입과 대규모 표 리팩터링은 범위에 포함하지 않는다.

## 확인한 근거

- `shared/api/client.ts`: timeout 이외의 쓰기 연결 실패/성공 응답 파싱 실패가 결과 불확실성을 잃는다.
- `project-table.tsx`: offset 허용 timestamp를 문자열 자동 정렬한다.
- `revenue-chart.tsx`: 최근 N일을 응답 배열의 마지막 N항목으로 계산한다.
- Orders/Customers 최초 조회 실패의 live footer가 0건으로 표시된다.
- E2E core/samples는 명시 파일 목록이며 신규 spec의 편입을 강제하지 않는다.

## 변경 경계

- `shared/api`, `shared/lib/i18n`: 오류 의미와 번역. GET/HEAD 재시도 안내는 유지한다.
- `entities/project`, `entities/analytics`, 해당 widgets: 불확실 mutation 재조회, 날짜 정렬/선택 계약.
- Orders/Customers와 차트 소비 화면: 기존 shadcn 구성에서 오류 안내와 접근성/반응형 보완.
- script/package/docs: 범주 완전성 가드레일, 도입 안내, 리뷰 결과. 저장 형식·환경 변수는 바꾸지 않는다.

## 실행과 검증

1. 통화 UI는 `pnpm check`와 현재 로컬 서버의 메뉴로 확인 후 별도 커밋·푸시한다.
2. 리뷰 결함별 의미 있는 회귀 테스트만 추가한다. 필요한 관련 파일 테스트 외에 로컬 전체 테스트/빌드를 실행하지 않는다.
3. 변경 통합 후 정적 검사와 필요한 UI 경계만 확인한다.
4. 전체 guardrail/unit/production E2E는 PR Actions에 맡기고 최종 main SHA도 성공을 확인한다.
5. 최종 점수·남은 보완점·검증 범위를 날짜가 있는 리뷰 문서에 기록한다.

## 완료 기록

- 통화 UI 정적 검사 통과, 한국어 KRW 메뉴에서 설명/날짜가 사라지고 Banknote가 표시됨을 확인했다.
- 모바일 390px 고객 상세는 정상, 320px에서 KRW 구매 금액이 카드 밖으로 넘침을 재현했다.
- 세 데이터 계약 결함, 초기 목록 오류 안내, 실제 차트 이름, 좁은 KRW 카드 경계를 수정했다. 320px 카드 너비는 269px, scroll 너비도 269px로 넘침이 없다. 390px에서는 두 열을 유지한다.
- `pnpm check` 통과. 관련 8개 파일/36개 단위 테스트와 E2E 범주 검사기의 6개 회귀 테스트 통과. 로컬 전체 테스트·빌드는 실행하지 않았다.
- [리뷰 결과](../reviews/boilerplate-readiness-2026-11-04.md)에 가중치, 84→92점 재평가, 확정 수정과 후속 개선을 구분했다. 원격 CI의 최종 실행 링크와 성공 여부는 PR 및 작업 완료 기록에 남긴다.

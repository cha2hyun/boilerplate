# 작업 계획: 페이지 기획과 디자인 일관성

상태: 구현 완료 · 최종 CI와 병합 결과는 [PR #23](https://github.com/cha2hyun/boilerplate/pull/23)에서 확인

## 문제와 완료 조건

- 사용자/상황: 사람과 AI가 페이지를 수정할 때 기존 제품 의도와 디자인 톤을 유지한다.
- 현재 동작: 공통 토큰·PageHeader·Stack은 보호되지만 현재 페이지 명세, KPI/밀도 조합, 긴 콘텐츠 기준, 시각 기준과 접근성 합격 조건의 연결이 부족하다.
- 완료 조건: 9개 페이지의 현재 기획과 소유 코드/검증 연결, 공통 KPI·페이지 간격, 긴 콘텐츠 처리, 대표 시각 회귀, 접근성/모션 검증을 구현한다.
- 범위 제외: 실제 인증/백엔드 도입, 페이지별 제품 동작의 임의 변경, 다른 디자인 시스템 의존성, 전체 로컬 테스트/빌드.

## 확인한 근거

- `docs/design-system.md`, `docs/url-state.md`, 페이지 코드, `e2e/workspace.spec.ts`, `playwright.config.ts`.
- 이전 main `dac6391`의 CI 성공 및 열린 Dependabot PR/보안 알림 없음 확인.
- 기간·초기화·저장 수명은 현재 구현을 명세로 기록하고, 제품 정책 변경은 별도 변경으로 다룬다.

## 변경 경계

- `docs/pages`는 페이지 기획의 유일한 서술 원본. 디자인 토큰/스키마/번역을 복제하지 않는다.
- 기존 shadcn Card/Stack/숫자 표시를 조합해 KPI를 공통화한다. 새 UI 프레임워크나 primitive는 도입하지 않는다.
- 시각·접근성 검사는 기존 production 번들과 core/samples의 2-job/2-worker 정책을 재사용한다.
- 기준 이미지는 Linux Actions 산출물을 실제 검토하고 커밋한다. 누락/차이를 자동 승인하지 않는다.

## 실행과 검증

1. 페이지 기획·문서 탐색·누락/링크 검사.
2. KPI·간격·긴 콘텐츠 계약과 구현.
3. reduced-motion·접근성 합격 조건 및 대표 시각 회귀.
4. 로컬 `pnpm check`; 필요한 검사기/결함만 선택 검증.
5. 기능별 커밋·푸시, PR 및 최종 main Actions 확인.

## 완료 기록

- 9개 페이지 기획 명세와 템플릿·탐색 경로·문서 검사기를 추가했다. 문서 전용 변경도 CI에서 경로 누락·깨진 링크·필수 섹션을 검사한다.
- 공통 MetricCard, 페이지 간격, 긴 금액과 상세 콘텐츠 표시 계약을 실제 화면에 적용했다. 로딩 전후 카드 크기와 큰 원화 금액은 세 화면 구간에서 검사한다.
- 데스크톱/모바일 KPI, 태블릿 주문 표, 폼 오류의 Linux Actions 이미지를 직접 검토해 기준으로 등록했다. 누락·차이는 실패하며 자동 갱신하지 않는다.
- 키보드 초점, 폼 오류 연결, reduced motion, 모바일 200% 글자 확대 검사를 기존 core 범주에 추가했다. 자동 접근성 검사의 범위와 한계도 문서화했다.
- 로컬 `pnpm check`, 문서 검사기 8개·숫자 표시 28개·설정 검증 1개의 선택 테스트를 통과했다. 전체 로컬 테스트·브라우저·빌드는 실행하지 않았다.
- Actions에서 품질·전체 단위/가드레일·production build와 samples 범주를 통과했다. 두 번째 core 실행은 행동 검사와 기존 기준 이미지가 통과했으며, 마지막 태블릿 기준 이미지의 최초 등록만 남아 실패했다. 이 이미지를 검토·반영했고 최종 SHA의 결과는 PR 검사를 기준으로 한다.
- 페이지 기획/구현 및 디자인·접근성 계약을 별도로 리뷰하고, 오래된 표 선택자와 문서 설명을 바로잡았다. 실제 백엔드·인증이나 모든 보조기술 준수를 구현했다고 간주하지 않는다.

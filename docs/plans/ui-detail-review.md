# UI 디테일·모바일 재검수

상태: 진행

## 문제와 완료 조건

기존 shadcn 디자인을 유지하면서 아홉 페이지와 주요 조작을 PC·태블릿·모바일에서 다시 확인합니다. 같은 역할의 제목·입력·버튼과 카드 경계가 일치하고, 320px 또는 큰 글자에서도 문구와 행동이 가려지지 않아야 합니다. 실제 발견한 문제만 고치며 새 디자인이나 기능을 추가하지 않습니다.

## 확인한 근거

- 시작 기준 main `c2c3967`, CI 성공. 변경 없는 상태에서 기존 production 번들로 검수했습니다.
- Overview/Analytics/Inbox: 320·390·834·1440px, 한영·다크/라이트 조합에서 페이지 가로 넘침과 공통 제목 치수를 확인했습니다. Overview 320px 차트 설명은 폭 90px에 네 줄, 툴팁 이름·값 사이 간격은 0px였습니다.
- 셸: 200% 글자에서 모바일 Sidebar가 화면을 넘고 검색 입력이 닫기 버튼과 겹칩니다. 짧은 가로 화면에서는 접힌 탐색 레일의 아래 메뉴에 스크롤로 도달할 수 없습니다.
- Settings/Components/Foundations: 320px 저장 버튼·탭 넘침, 나란한 카드의 하단 불일치, 전체 확인 경로 없는 제목 축약을 발견했습니다.
- Projects/Customers: 공백 없는 긴 이름이 삭제 확인창을 늘리고, 200% 고객 생성 버튼이 모달 너비를 넘습니다. Orders의 기존 날짜 정규화와 일반 모달 치수는 유지됐습니다.
- Orders: 짧은 화면에서 초기/순환 키보드 초점의 이름 입력이 독립 스크롤 본문 밖에 남았습니다. 해당 필드에 초점이 올 때 실제 본문 위치를 복구합니다.
- 추가 요청: 모바일 KPI가 지나치게 크다는 피드백을 반영해 공통 최소 높이를 192px에서 136px로 줄입니다. 태블릿/PC는 유지하고 긴 값·확대 글자는 자연 확장합니다.
- 200% 글자 검수에서 Analytics 기기 레이블·비율 행과 Inbox 제목·배지·탭·상세 행동의 잘림도 확인했습니다.
- 캡처와 좌표는 `/tmp/blueprint-ui-audit/`에 저장합니다. 기기별 native Safari나 OS 확대를 검증했다고 표현하지 않습니다.

## 변경 경계

- `shared/ui`: Sidebar·Command·Chart·Tabs·MetricCard의 기존 조합을 보완합니다. 새 primitive·패키지·CSS 파일을 추가하지 않습니다.
- 페이지/feature/widget: 설정·예시 탭/카드·긴 문구와 삭제/고객 폼·작은 차트 헤더를 조정합니다.
- API·URL·영구 저장 형식과 데이터 모델은 변경하지 않습니다. 기존 초점·취소·미저장 보호·조회 캐시를 보존합니다.
- 에이전트는 셸, 상거래, 지원 페이지로 파일 소유권을 나누고 root가 Overview/차트와 최종 검증을 통합합니다.

## 실행과 검증

1. 실제 스크린샷/좌표로 재현한 결함을 최소 수정합니다. `overflow-hidden`으로 결함을 감추지 않습니다.
2. 관련 페이지 명세·공통 디자인 규칙과 기존 E2E의 기하·행동 조건을 함께 갱신합니다. 새 CI job이나 dev/prod 중복 테스트를 만들지 않습니다.
3. `pnpm check` 후 수정 번들로 해당 화면과 조작만 선택 검증합니다. 전체 단위/브라우저 검사는 Actions에서 수행합니다.
4. 원래 화면 크기·일반 글자 크기에서도 디자인과 동작이 유지되는지 비교합니다. 한·영 및 다크·라이트 대표 조합을 포함합니다.
5. 기능 변경을 커밋·푸시하고 PR/최종 main SHA의 CI를 확인합니다.

## 완료 기록

- 아홉 페이지의 24px/600 제목·배지·푸터 중심과 페이지 가로 넘침을 확인했습니다. 좁은 폭/200%에서는 전체 텍스트·컨트롤 도달·키보드 초점 경계를 별도로 확인했습니다.
- 모바일 KPI는 136px로 축소했고 Overview·Analytics·Orders·Customers의 실제 데모 요청에서 로딩/성공·캐시 치수 검사가 통과했습니다. 768px 이상은 192px를 유지합니다.
- 긴 이름의 프로젝트/고객 삭제, 고객 확대 폼, 짧은 주문 폼의 초기/순환 초점, 모바일 셸/검색, 작은 가로 화면 탐색, 공통 카드 정렬, 차트/Inbox의 확대 텍스트를 선택 검증했습니다.
- 키보드 탭 검증에서 실제 `transition-all` 크기 전환 문제가 추가로 확인돼 공통 TabsTrigger를 색상·테두리·그림자 전환으로 제한했습니다. 테스트에 sleep을 추가해 현상을 숨기지 않았습니다.
- 툴팁은 기존 Recharts의 실제 차트/plot 치수와 내용 폭을 사용합니다. 좁을 때만 위치·행을 바꾸고 정상 크기의 포인터 배치와 최소 간격을 유지합니다. 컴팩트 배치의 폭 변화가 재측정/배치 전환을 반복하지 않도록 열린 동안 측정 폭을 보존합니다.
- 전체 단위·브라우저 검사는 Actions가 담당합니다. 의도적으로 바뀐 모바일 KPI Linux 기준 이미지는 CI의 actual/diff를 직접 검토한 뒤 갱신합니다. PR/최종 main 결과는 해당 실행과 연결해 확인합니다.
- 실제 iPhone Safari, OS 글꼴 설정, 공간을 차지하는 일반 OS 스크롤바는 이번 Chromium 검증 범위 밖입니다. LAN 개발 서버는 계속 유지합니다.

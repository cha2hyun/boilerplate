# UI 라이팅

문구는 구현의 내부 단계를 설명하기보다 사용자가 한 행동과 확인할 결과를 말합니다. 서비스의 기본 말투는 [보이스와 톤](voice-and-tone.md)을 따릅니다.

| 위치        | 계약                      | 예시                                                |
| ----------- | ------------------------- | --------------------------------------------------- |
| 페이지 제목 | 하나의 작업/대상          | 프로젝트                                            |
| 주요 버튼   | 동사 + 필요한 대상        | 프로젝트 만들기, 변경 사항 저장                     |
| 입력 레이블 | placeholder와 별개로 유지 | 프로젝트 이름                                       |
| 입력 도움말 | 허용 범위/형식            | 2~80자로 입력하세요.                                |
| 필드 오류   | 바로 고칠 방법            | 프로젝트 이름을 2자 이상 입력해 주세요.             |
| 저장 성공   | 실제 완료한 행동          | 프로젝트를 만들었어요.                              |
| 요청 오류   | 실패한 대상 + 다음 행동   | 변경 사항을 저장하지 못했어요. 다시 시도해 주세요.  |
| 빈 검색     | 결과 상태 + 복구 행동     | 일치하는 프로젝트가 없어요. 필터를 초기화해 보세요. |

하나의 문장에는 한 가지 정보를 담습니다. 같은 대상을 프로젝트/작업/항목으로 번갈아 부르지 않습니다. `확인`, `처리`, `완료`만으로 행동을 감추지 않습니다. 기술적 오류 코드와 stack trace는 사용자 본문에 출력하지 않으며, 지원에 필요한 식별자는 별도로 제공합니다.

중요한 오류는 해당 필드나 작업 영역에 남기고 입력값을 유지합니다. 재시도 버튼은 실제 재요청에 연결합니다. Toast는 보조 확인용이며 사용자가 반드시 해야 할 행동을 toast에만 두지 않습니다. 접근 가능한 이름은 보이는 버튼 문구와 일치시킵니다.

숫자는 숫자로 표기하고 기간·단위·범위를 생략하지 않습니다. `12` 대신 문맥에 따라 `프로젝트 12개`, `최근 7일`처럼 씁니다. 문구에 넣는 수량도 [숫자 표시](../number-formatting.md)의 공통 함수를 거칩니다. 날짜·지역별 표현과 향후 복수형은 [국제화](international-design.md)를 따릅니다. 이메일·고객명 등 데이터는 문구에 불필요하게 반복하지 않습니다.

## 참고 자료의 적용 범위

[SEED Writing](https://seed-design.io/foundations/writing)에서 익숙한 단어, 목적 중심 문구, 오류 해결 안내의 관점을 참고했습니다. 당근의 기능명·문장·캠페인 표현은 복사하지 않으며 위 관리자 예시와 API가 보장하는 결과를 사용합니다.

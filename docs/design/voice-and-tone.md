# 보이스와 톤

Blueprint의 문장은 운영자가 **현재 상태와 다음 행동을 빠르게 판단**하도록 돕습니다. 차분하고 직접적인 말투를 사용하며 성공·오류·삭제 상황에서도 같은 용어를 유지합니다.

| 상황        | 말하는 방법                         | 예시                                                 |
| ----------- | ----------------------------------- | ---------------------------------------------------- |
| 일반 안내   | 필요한 사실과 다음 행동             | 프로젝트를 만들고 담당자를 지정하세요.               |
| 성공        | 실제로 끝난 행동과 범위             | 프로젝트 이름을 변경했어요.                          |
| 오류        | 실패한 작업 + 확인된 원인/다음 행동 | 목록을 불러오지 못했어요. 다시 시도해 주세요.        |
| 파괴적 행동 | 대상·영향·복구 가능 여부를 명시     | 이 프로젝트를 삭제할까요? 삭제하면 복구할 수 없어요. |
| 빈 상태     | 비어 있는 이유와 가능한 행동        | 검색 결과가 없어요. 검색어나 필터를 바꿔보세요.      |

원인을 모르면 네트워크·권한·서버 장애로 단정하지 않습니다. 사용자를 탓하거나 과장된 감탄, 의인화, 불필요한 사과를 반복하지 않습니다. 파괴적 작업은 실제 복구 계약을 확인한 뒤 경고합니다. 데모에는 데모라는 범위를 명시하고 저장·발송·결제 성공을 꾸며내지 않습니다.

한국어 안내 문장은 자연스러운 존댓말로 작성하고 버튼/메뉴는 짧은 동작명으로 씁니다. 오류와 삭제를 장난스럽게 표현하지 않습니다. 문장별 세부 규칙은 [라이팅](writing.md)에서 관리합니다.

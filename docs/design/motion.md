# 모션의 목적

모션은 값·상태·초점의 변화를 이해할 때만 사용합니다. 메뉴/대화상자는 설치된 shadcn의 동작을 유지하고 페이지 진입마다 장식적인 이동·확대·순차 등장을 추가하지 않습니다. 정보가 읽히거나 작업을 시작하는 시점을 모션 끝까지 늦추지 않습니다.

**시간, 지연, skeleton, 숫자 전환, reduced-motion의 구현 계약은 [로딩과 모션](../loading-and-motion.md) 한 곳에서 관리합니다.** 이 문서나 페이지 예시에서 별도의 duration 또는 대기 타이머를 만들지 않습니다.

검토할 질문:

- 변화가 없는데 움직이지 않는가? 사용자 행동이나 실제 데이터 변화와 연결되는가?
- 로딩 중에도 기존 데이터와 레이아웃, 키보드 초점을 유지하는가?
- 움직임 없이도 상태·결과·오류를 이해할 수 있는가?
- OS의 움직임 줄이기를 존중하고 화면낭독기에 중간 숫자를 반복해서 읽히지 않는가?

## 참고 자료의 적용 범위

[SEED Motion](https://seed-design.io/foundations/motion)에서 작은 반응과 큰 화면 변화의 목적을 구분하는 관점을 참고했습니다. SEED의 duration/easing 토큰, 눌림 효과, expressive 전환을 복제하지 않습니다. 우리 앱의 구현 계약과 shadcn 동작을 우선합니다.

# 접근성 합격 조건

이 문서는 화면 변경의 접근성 완료 조건을 소유합니다. 구현은 기존 shadcn 컨트롤과 의미 있는 HTML을 사용하며, 모션의 구현값은 [로딩과 모션](../loading-and-motion.md), 색상 역할은 [색상](color.md), 긴 콘텐츠와 배치는 [레이아웃](layout.md)을 따릅니다.

## 이름, 구조, 상태

- 페이지 h1은 하나이며 제목 계층과 landmark는 실제 문서 구조를 나타냅니다. 아이콘만 있는 버튼에는 작업을 설명하는 접근 가능한 이름을 제공합니다. 장식 아이콘은 `aria-hidden`으로 숨기고 Tooltip을 유일한 이름으로 사용하지 않습니다.
- 입력은 연결된 Label을 사용합니다. placeholder는 이름을 대신하지 않습니다. 오류에는 텍스트 설명과 `aria-invalid`, 해당 설명을 가리키는 `aria-describedby`를 함께 제공합니다. 수정하면 오래된 오류와 참조를 제거하고 필요한 안내는 유지합니다.
- 색이나 아이콘만으로 상태를 구분하지 않습니다. 로딩·오류·선택 상태의 텍스트/역할을 유지하며 동일한 결과를 여러 live region으로 반복하지 않습니다. 숫자 모션은 최종값만 접근성 트리에 제공합니다.

## 키보드와 초점

Tab/Shift+Tab으로 행동에 도달하고 Enter/Space 및 컨트롤의 표준 방향키로 조작할 수 있어야 합니다. 마우스로 클릭한 뒤 `focus()`를 호출한 결과는 키보드 탐색을 검증한 것으로 보지 않습니다. `:focus-visible` 표시를 제거하거나 내용/고정 영역 뒤로 초점을 가리지 않습니다.

Dialog/Sheet는 제목·설명·초점 진입과 모달 안의 순환을 유지합니다. Escape 또는 취소로 닫으면 연 컨트롤로 돌아갑니다. 미저장 변경이 있는 폼은 [입력 보호](../unsaved-changes.md)에 따라 먼저 폐기 의사를 확인하며, 계속 편집을 선택하면 기존 입력으로 초점을 돌립니다. 삭제로 그 컨트롤이 없어졌다면 목록 제목처럼 다음 작업을 이해할 수 있는 위치로 이동합니다. 메뉴/Select의 방향키·선택·Escape와 초점 복귀는 설치된 Radix 동작을 유지합니다. 서버 저장 중 닫기를 제한하는 기존 정책은 안내와 비활성 상태를 함께 유지합니다.

## 확대, 대비, 검증 경계

가로로 넘치는 탭은 키보드로 초점을 옮겼을 때 해당 탭 전체가 스크롤 영역 안에 드러나야 합니다. 공통 TabsTrigger는 색상·배경·테두리·그림자만 전환하며 글자 크기나 padding을 애니메이션하지 않습니다. 확대 중 과거 치수를 기준으로 초점을 스크롤한 뒤 탭이 다시 가려지는 문제가 없어야 합니다.

대표 모바일 화면은 412px에서 root 글꼴을 200%로 늘려 확인합니다. 페이지 가로 스크롤이 없는 것만으로 통과하지 않습니다. 셸의 핵심 버튼이 잘리지 않고, 폼 오류와 저장/닫기 행동을 화면 또는 대화상자 내부 세로 스크롤로 읽고 조작할 수 있어야 합니다. 모바일 사이드바는 320px까지 폭을 줄여도 viewport 안에 맞고, 화면 안의 닫기 버튼을 터치해 탐색 없이 닫을 수 있어야 합니다. 검색 팔레트는 입력 영역과 닫기 버튼의 공간을 분리하여 긴 입력과 placeholder가 겹치지 않아야 합니다. `overflow-hidden`으로 넘친 내용을 감추는 것은 해결이 아닙니다. 이 검사는 브라우저의 실제 확대 기능이나 모든 사용자 글꼴 설정을 대신하지 않습니다.

일반 텍스트의 전경/배경 대비는 4.5:1, 큰 텍스트는 3:1, 컨트롤 경계와 초점 표시는 인접 색과 3:1을 기준으로 검토합니다. light/dark의 실제 합성 색과 disabled·hover·선택 상태를 구분하고, 토큰 이름만 보고 적합하다고 판단하지 않습니다. 기본 토큰 쌍 검사가 통과해도 차트·투명 배경·전체 컨트롤 상태의 적합성을 보장하지 않습니다.

`e2e/accessibility.spec.ts`는 기존 production preview와 `e2e/fixtures.ts`를 사용해 다음 대표 계약을 검사합니다.

- Components Dialog: 실제 Tab 진입, 표시 가능한 키보드 초점, 양방향 순환, 접근 가능한 제목/설명과 아이콘 닫기 이름, Escape 후 복귀.
- Projects 폼: 오류의 접근 가능한 설명, 수정 후 오류 해제, Select 방향키 선택과 닫기/복귀.
- OS reduced motion: 실행 중 설정 변경과 Dialog/AlertDialog/메뉴/Select/Tooltip/모바일 Sheet, Skeleton·spinner, Progress/Switch/Sidebar의 공간 전환. 노출된 데모가 없는 Popover/Submenu는 같은 공유 구현을 적용하며 이 E2E가 직접 행사하지는 않습니다.
- 모바일 200% 글꼴: 핵심 셸 행동의 화면 내 표시, 320–412px 사이드바 폭과 터치 닫기, 검색 입력·닫기 버튼의 비겹침, 오류·저장 행동 도달, 폼의 가로 잘림 방지.
- 높이 390px의 접힌 탐색 레일: 세로 스크롤로 하단 설정 항목에 도달하고 선택할 수 있는지 확인.

대표 대비와 시각 회귀는 `e2e/design-visual.spec.ts`, 기존 생성/수정/삭제 이후 초점 복귀는 `e2e/projects.spec.ts`도 함께 확인합니다. 실행 범위는 [테스트 정책](../testing.md)을 따릅니다. 자동 검사를 전체 WCAG 준수나 화면낭독기 검증으로 표현하지 않습니다. 화면낭독기·브라우저 확대·실제 모바일 보조기술 검증은 수행한 환경과 결과를 별도로 기록합니다.

차트 축 글자는 실제 SVG `.recharts-cartesian-axis-tick-value`의 computed `fill`과 카드 배경으로 대비를 확인합니다. 공통 Chart가 `muted-foreground`를 적용하며 Recharts 내부 그룹 구조가 달라져도 텍스트 자체를 대상으로 합니다. `e2e/design-visual.spec.ts`의 `renders readable chart axes and avatar initials in both themes`는 Overview·Analytics의 두 테마에서 토큰 적용과 4.5:1을 함께 확인합니다. 토큰 쌍만 통과한 결과로 실제 차트의 가독성을 대신 판단하지 않습니다.

Avatar의 이니셜과 그룹 인원 수는 `bg-muted` 위에 `text-foreground`를 사용합니다. 밝은 테마의 `muted-foreground` 조합은 12px 이니셜에서 4.34:1로 부족했으므로 사용하지 않습니다. 같은 브라우저 회귀가 Overview·Projects의 실제 Avatar 텍스트와 배경 대비도 두 테마에서 확인합니다.

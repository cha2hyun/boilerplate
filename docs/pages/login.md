# Login

<!-- page-route: /login -->

## 목적과 범위

현재 탭의 데모 워크스페이스로 들어가는 화면입니다. 기본 로그인과 Microsoft 버튼 모두 같은 샘플 계정을 사용합니다. Microsoft 계정 인증·연결이나 서버 권한 검사는 제공하지 않습니다. API 모드에서는 데모 폼 대신 연결 안내와 공개 대시보드 링크를 표시합니다. [로그인 라우트](../../src/app/routes/login.tsx)

## 정보 구조와 주요 행동

사이드바가 없는 독립된 본문에 제품 이름·언어 메뉴, PageHeader, 이메일·비밀번호 입력과 기본 **로그인** 버튼을 차례로 표시합니다. 그 아래 `또는` / `or` 구분선과 **Microsoft로 로그인** / **Sign in with Microsoft** 버튼이 있습니다. 폼 아래의 **대시보드 둘러보기** 링크는 세션 없이 `/`를 엽니다. 언어 메뉴에서 한국어·영어를 전환할 수 있습니다.

## 조회·조작 계약

- 이메일과 비밀번호는 편집 가능한 데모 값으로 시작합니다. 값을 그대로 제출하거나 수정 후 제출할 수 있습니다. 기본 로그인은 이메일 앞뒤 공백과 대소문자를 정규화하고 비밀번호가 데모 값과 정확히 일치하는지 확인합니다. 빈 값이나 일치하지 않는 입력은 거절합니다.
- Microsoft 버튼은 현재 탭에서 고정 데모 사용자 세션을 열고 기본 로그인과 같은 성공 콜백을 실행합니다. 외부 인증 창이나 토큰 교환, 입력한 이메일·비밀번호 전송은 없습니다.
- 어느 방법으로 들어가든 `sessionStorage`에는 데모 ID 하나만 저장합니다. 새로고침하면 유효한 ID를 복원하고 로그아웃하면 전용 키를 삭제합니다. 이메일·비밀번호는 URL·저장소·로그·HTTP 요청에 싣지 않습니다. 저장소를 쓸 수 없으면 현재 문서의 메모리에서만 세션을 유지합니다.
- 사용자 목록이나 상세를 즐겨찾기에서 열었을 때도 로그인 후에는 검증된 `/users` 조회 조건으로 돌아갑니다. 그 밖의 목적지는 `/account`를 사용합니다. 유효한 세션으로 `/login`에 재진입하거나 로그아웃 후 뒤로 갈 때도 라우트가 세션을 확인합니다. [복귀 경로 검증](../../src/app/demo-access/destination.ts)

## 상태별 화면

처음에는 두 입력에 데모 값이 보이고 비밀번호는 마스킹됩니다. 기본 로그인 실패 시 해당 입력에 오류 설명을 연결하고 첫 오류 입력으로 초점을 보냅니다. 필드를 수정하면 그 필드의 오류를 해제합니다. 데모 세션 생성은 동기 처리이므로 네트워크 로딩·재조회·재시도 상태는 없습니다. 입력 초안은 화면을 떠나면 폐기합니다.

## 반응형 동작

| 구간                | 배치·스크롤·초점                                                                                                                                                     |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 모바일 `<768px`     | 한 열에 입력, 기본 로그인, 구분선, Microsoft 버튼을 배치합니다. 확대하거나 높이가 짧은 화면에서도 세로 스크롤로 오류·두 로그인 버튼·대시보드 링크에 도달해야 합니다. |
| 태블릿 `768–1279px` | 가운데 배치한 한 열 카드에서 언어 메뉴 → 이메일 → 비밀번호 → 기본 로그인 → Microsoft 버튼 → 대시보드 링크 순으로 키보드 탐색합니다. 구분선은 Tab 정지점이 아닙니다.  |
| PC `≥1280px`        | 같은 최대 폭을 유지합니다. Enter로 폼을 제출하거나 Microsoft 버튼을 키보드로 실행할 수 있습니다.                                                                     |

## 상태 소유권과 구현 근거

- URL·복귀·API 모드 안내는 [로그인 라우트](../../src/app/routes/login.tsx)와 [목적지 검증](../../src/app/demo-access/destination.ts)이 관리합니다.
- 데모 값 검증, 탭 ID 저장·복원·로그아웃은 [세션 모델](../../src/features/demo-session/model/session.ts)이 담당합니다. 셸과 라우트는 [feature 공개 API](../../src/features/demo-session/index.ts)를 사용합니다.
- [LoginPage](../../src/pages/login/ui/login-page.tsx)는 입력 초기값·편집·오류·초점, 두 로그인 동작과 성공 콜백을 소유합니다. 언어는 기존 [국제화 계약](../i18n.md)을 따릅니다.

## 수용 기준

- 초기 데모 값으로 기본 로그인 → 같은 탭에 데모 ID를 저장하고 허용한 화면으로 복귀합니다. 입력을 지우거나 틀린 값으로 바꾸어 제출 → 첫 오류 입력으로 초점이 이동하고 세션은 생성되지 않습니다. [폼 단위 검사](../../src/pages/login/ui/login-page.test.tsx)
- Microsoft 버튼 선택 → 외부 서비스로 이동하지 않고 같은 데모 ID를 저장하여 동일한 목적지로 복귀해야 합니다. 한국어·영어 버튼 이름과 구분선, 모바일에서 두 동작 도달 여부도 화면 검증 대상입니다. [로그인 화면](../../src/pages/login/ui/login-page.tsx) · [폼 단위 검사](../../src/pages/login/ui/login-page.test.tsx)
- 유효한 ID만 복원·탭 분리·로그아웃·저장소 실패 시 메모리 대체는 [세션 단위 검사](../../src/features/demo-session/model/session.test.ts)의 `tab demo session` 시나리오로 확인합니다. 즐겨찾기와 같은 사용자 상세 직접 링크의 복귀, 로그아웃 후 브라우저가 복원한 보호 화면의 세션 재확인은 [워크스페이스 브라우저 검사](../../e2e/workspace-users.spec.ts)를 따릅니다.

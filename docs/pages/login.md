# Login

<!-- page-route: /login -->

## 목적과 범위

현재 탭의 데모 워크스페이스로 들어가는 화면입니다. 기본 로그인과 Microsoft 버튼 모두 같은 샘플 계정을 사용합니다. Microsoft 계정 인증·연결이나 서버 권한 검사는 제공하지 않습니다. API 모드에서는 데모 폼 대신 연결 안내와 공개 대시보드 링크를 표시합니다. [로그인 라우트](../../src/app/routes/login.tsx)

## 정보 구조와 주요 행동

상단 헤더는 화면 폭을 사용하고, 왼쪽에 제품 로고와 이름, 오른쪽에 언어 메뉴를 둡니다. 본문 로그인 영역에는 공통 PageHeader, 이메일·비밀번호 입력과 기본 **로그인** 버튼을 차례로 표시합니다. 그 아래 `또는` / `or` 구분선과 **Microsoft로 로그인** / **Sign in with Microsoft** 버튼이 있습니다. 폼 아래 **데모 응답**에서 다음 로그인 요청의 동작을 고를 수 있습니다. **대시보드 둘러보기** 링크는 세션 없이 `/`를 엽니다. 언어 메뉴에서 한국어·영어를 전환할 수 있습니다. PC에서는 로그인 영역 오른쪽에 **샘플** 표시와 함께 주문 미리보기를 둡니다. 주문번호·상태·USD 합계를 텍스트 표로 읽을 수 있고, 행과 상태는 클릭하거나 선택하는 컨트롤이 아닙니다.

## 조회·조작 계약

- 주문 미리보기는 공개용 고정 세 행만 사용합니다. 순서대로 `ORD-1042` 처리 중 123 USD, `ORD-1041` 배송 중 80 USD, `ORD-1040` 배송 완료 149 USD입니다. 상태와 금액 표기는 화면 언어를 따릅니다. 미리보기를 표시하기 위해 주문 API·환율을 요청하거나 브라우저에 저장된 주문을 읽지 않습니다. 고객 이름·이메일도 표시하지 않습니다.
- 이메일과 비밀번호는 편집 가능한 데모 값으로 시작합니다. 값을 그대로 제출하거나 수정 후 제출할 수 있습니다. 기본 로그인은 이메일 앞뒤 공백과 대소문자를 정규화하고 비밀번호가 데모 값과 정확히 일치하는지 확인합니다. 빈 값과 일치하지 않는 입력에는 필드별 오류를 표시합니다. 자격 증명 판정은 데모 API가 담당합니다.
- 두 버튼 모두 같은 출처의 `POST /api/demo-login`으로 로그인합니다. 기본 로그인은 폼 값을 JSON 본문으로 보내며 Microsoft 버튼은 로그인 방식과 응답 시나리오만 보냅니다. 둘 다 검증된 성공 응답에서만 세션을 열고 같은 복귀 경로로 이동합니다. [HTTP 계약](../api-contract.md#데모-로그인)
- 어느 방법으로 들어가든 `sessionStorage`에는 데모 ID 하나만 저장합니다. 새로고침하면 유효한 ID를 복원하고 로그아웃하면 전용 키를 삭제합니다. 이메일·비밀번호를 URL·저장소·로그에 넣지 않습니다. 저장소를 쓸 수 없으면 현재 문서의 메모리에서만 세션을 유지합니다.
- 사용자 목록이나 상세를 즐겨찾기에서 열었을 때도 로그인 후에는 검증된 `/users` 조회 조건으로 돌아갑니다. 그 밖의 목적지는 `/account`를 사용합니다. 유효한 세션으로 `/login`에 재진입하거나 로그아웃 후 뒤로 갈 때도 라우트가 세션을 확인합니다. [복귀 경로 검증](../../src/app/demo-access/destination.ts)

## 상태별 화면

| 상태           | 확인 방법과 화면 동작                                                                                                                                            |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 준비           | 데모 이메일과 마스킹한 비밀번호가 입력되어 있습니다. 응답 설정은 기본 동작으로 시작합니다.                                                                       |
| 요청 중        | 버튼을 누르면 선택한 로그인 방법에 처리 중 표시가 나타나고 중복 제출을 막습니다. 두 로그인 방식 모두 느린 응답을 선택해 약 2.5초간 관찰할 수 있습니다.           |
| 자격 증명 오류 | 다른 비밀번호로 기본 로그인하면 목업이 401을 반환합니다. 화면은 첫 오류 입력으로 초점을 옮기고 필드별 오류를 설명합니다. 값을 고친 뒤 다시 로그인할 수 있습니다. |
| 서비스 오류    | 서버 오류를 선택하면 목업이 503을 반환합니다. 폼 값을 보존하고 오류를 표시합니다. 선택한 시뮬레이션은 한 번만 적용되어 같은 버튼으로 재시도할 수 있습니다.       |
| 성공·이탈      | 검증된 응답에서 세션을 열고 원래 목적지로 돌아갑니다. 응답 전에 폼을 떠나면 요청을 취소하고 뒤늦게 세션을 열지 않습니다.                                         |

## 반응형 동작

| 구간                            | 배치·스크롤·초점                                                                                                                              |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 모바일 (<48rem)                 | 헤더 아래 한 열로 입력·기본 로그인·Microsoft 버튼·대시보드 링크를 표시합니다. 오류·확대·짧은 높이에서도 세로 스크롤로 모든 동작에 도달합니다. |
| 태블릿 (48rem 이상, 80rem 미만) | 폼은 중앙의 한 열로 유지합니다. 주문 미리보기는 작은 화면의 스크롤이나 탭 순서에 포함되지 않습니다.                                           |
| PC (80rem 이상)                 | 왼쪽에 로그인 폼, 오른쪽에 비대화형 주문 미리보기를 나란히 표시합니다. 넓은 화면에서도 입력의 읽기 폭을 제한합니다.                           |

기본 글꼴 크기에서 두 열로 전환되는 경계는 1280px입니다. 어느 구간에서도 폼의 키보드 순서는 이메일 → 비밀번호 → 기본 로그인 → Microsoft 버튼이며, 구분선·미리보기에는 Tab 정지점이 없습니다.

## 상태 소유권과 구현 근거

- URL·복귀·API 모드 안내는 [로그인 라우트](../../src/app/routes/login.tsx)와 [목적지 검증](../../src/app/demo-access/destination.ts)이 관리합니다.
- [요청·응답 모델](../../src/features/demo-session/model/login-contract.ts)과 [로그인 요청](../../src/features/demo-session/api/login.ts)이 자격 증명과 응답 형식을 검증합니다. [세션 모델](../../src/features/demo-session/model/session.ts)은 탭 ID 저장·복원·로그아웃을 담당합니다. 셸과 라우트는 [feature 공개 API](../../src/features/demo-session/index.ts)를 사용합니다.
- [주문 미리보기](../../src/pages/login/ui/login-workspace-preview.tsx)는 공개 샘플 상수와 번역·표시 형식만 소유합니다. 주문 Query나 고객 데이터를 사용하지 않습니다.
- [LoginPage](../../src/pages/login/ui/login-page.tsx)는 입력 초기값·편집·오류·초점, 두 로그인 동작, 대기·오류 표시와 요청 취소를 소유합니다. 언어는 기존 [국제화 계약](../i18n.md)을 따릅니다.

## 수용 기준

- 기본 글꼴·1440px 화면에서 헤더 로고와 언어 메뉴는 폼 폭에 묶이지 않고, 로그인 폼과 샘플 주문 표가 좌우로 보입니다. 1280px에서 표가 보이고 1279px·834px·390px에서는 한 열 폼만 보여야 합니다. 양쪽 로그인 방법·언어 메뉴·대시보드 링크에는 키보드로 접근할 수 있어야 합니다.
- 주문 예시는 고객 정보 없이 지정된 세 행을 읽을 수 있어야 하고, 의미 있는 열 머리글과 상태 텍스트를 제공합니다. 로그인 전 주문/환율 조회나 주문 저장소 읽기에 미리보기 내용이 의존하지 않아야 합니다.
- 느린 응답을 선택하고 로그인하면 응답 전에 두 로그인 버튼의 중복 제출이 차단되며 세션 키는 비어 있어야 합니다. 서버 오류를 선택하면 로그인 화면에서 오류가 보이고 다시 시도하면 새 요청으로 성공해야 합니다. [목업 API 검사](../../src/app/mocks/demo-login.test.ts)
- 초기 데모 값으로 기본 로그인 → 같은 탭에 데모 ID를 저장하고 허용한 화면으로 복귀합니다. 입력을 지우거나 틀린 값으로 바꾸어 제출 → 첫 오류 입력으로 초점이 이동하고 세션은 생성되지 않습니다. [폼 단위 검사](../../src/pages/login/ui/login-page.test.tsx)
- Microsoft 버튼 선택 → 외부 서비스로 이동하지 않고 같은 데모 ID를 저장하여 동일한 목적지로 복귀해야 합니다. 한국어·영어 버튼 이름과 구분선, 모바일에서 두 동작 도달 여부도 화면 검증 대상입니다. [로그인 화면](../../src/pages/login/ui/login-page.tsx) · [폼 단위 검사](../../src/pages/login/ui/login-page.test.tsx)
- 유효한 ID만 복원·탭 분리·로그아웃·저장소 실패 시 메모리 대체는 [세션 단위 검사](../../src/features/demo-session/model/session.test.ts)의 `tab demo session` 시나리오로 확인합니다. 즐겨찾기와 같은 사용자 상세 직접 링크의 복귀, 로그아웃 후 브라우저가 복원한 보호 화면의 세션 재확인은 [워크스페이스 브라우저 검사](../../e2e/workspace-users.spec.ts)를 따릅니다.

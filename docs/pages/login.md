# Login

<!-- page-route: /login -->

## 목적과 범위

공개 샘플 계정으로 현재 탭의 데모 워크스페이스에 들어갑니다. 이메일·비밀번호를 실제 서비스로 보내거나 사용자 권한을 판단하는 기능은 없습니다. 공개 값은 폼 위에서 확인하고 한 번에 채울 수 있습니다. API 모드에서의 안내와 이후 이동은 [로그인 라우트](../../src/app/routes/login.tsx)가 소유합니다.

## 정보 구조와 주요 행동

사이드바가 없는 독립된 본문입니다. 제품 이름·언어 메뉴 → PageHeader → 공개 계정 값과 채우기 → 이메일·비밀번호·로그인 → 공개 대시보드 링크 순서로 표시합니다. 대시보드 링크는 세션 없이 `/`를 엽니다. 언어 메뉴는 앱의 한국어·영어 환경 설정을 변경합니다. 공개 값 채우기는 두 입력을 채우고 제출 버튼에 초점을 줍니다. Enter로 제출하거나 각 필드에 직접 입력할 수 있습니다.

## 조회·조작 계약

- 이메일 앞뒤 공백과 대소문자를 정규화합니다. 비밀번호는 표시된 값과 정확히 일치해야 합니다. 빈 값이나 다른 입력은 거절하고 세션을 만들지 않습니다.
- 성공하면 탭의 `sessionStorage`에 고정 데모 ID 하나를 저장하고 라우트의 콜백으로 이동합니다. 성공 후 비밀번호 초안을 비웁니다. 이메일·비밀번호는 URL·저장소·로그·HTTP 요청에 싣지 않습니다. 같은 탭의 새로고침은 유효한 ID만 복구하고 로그아웃은 전용 키만 삭제합니다.
- 저장소에 접근하거나 쓸 수 없으면 현재 문서의 메모리에 세션을 유지합니다. 이 경우 새로고침 후에는 다시 공개 계정으로 들어갑니다. 언어 설정은 기존 [국제화 계약](../i18n.md)을 따릅니다.
- 로그인 성공 시 `returnTo`의 허용 목적지 복원, 유효한 세션으로 `/login` 재진입, 로그아웃 및 뒤로 가기는 라우트가 소유합니다. [복귀 경로 검증](../../src/app/demo-access/destination.ts)에 따라 허용한 내부 경로만 사용합니다. 로그인 필드에는 이탈 보호나 자동 초안 복원을 적용하지 않습니다.

## 상태별 화면

초기 입력은 비어 있고 공개 값은 항상 표시됩니다. 제출 오류는 해당 입력과 텍스트로 연결하고 첫 오류 입력으로 초점을 보냅니다. 수정한 필드의 오류는 즉시 해제합니다. 네트워크 요청 없이 공개 값만 비교하므로 서버 로딩·재조회·재시도·빈 목록 상태는 없습니다. 키보드와 터치로 직접 입력하거나 공개 값을 채울 수 있으며 클립보드 접근이 필요하지 않습니다.

## 반응형 동작

| 구간                | 배치·스크롤·초점                                                                                                                                     |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 모바일 `<768px`     | 한 열 폼으로 표시하고 긴 이메일·오류·버튼 문구를 줄바꿈합니다. 확대하거나 화면 높이가 짧으면 페이지를 세로로 스크롤해 입력과 제출 버튼에 도달합니다. |
| 태블릿 `768–1279px` | 가운데에 읽기 쉬운 폭의 한 열 카드를 배치합니다. 언어 메뉴, 공개 값 채우기, 입력, 제출 순서로 키보드 탐색이 가능합니다.                              |
| PC `≥1280px`        | 같은 최대 폭의 단일 폼을 유지합니다. 입력 오류·데모 값 채우기 이후 초점 흐름은 모바일과 같습니다.                                                    |

## 상태 소유권과 구현 근거

- URL·복귀·세션 재진입은 [로그인 라우트](../../src/app/routes/login.tsx)와 [목적지 검증](../../src/app/demo-access/destination.ts)이 관리합니다. 폼에 별도 Query를 만들지 않습니다.
- 공개 값 검증, 탭 ID 저장·복원·로그아웃은 [세션 모델](../../src/features/demo-session/model/session.ts)이 담당합니다. 셸과 라우트는 [feature 공개 API](../../src/features/demo-session/index.ts)를 사용합니다.
- [LoginPage](../../src/pages/login/ui/login-page.tsx)는 이메일·비밀번호 초안, 입력 오류, 초점과 성공 콜백을 소유합니다. 창의 언어 상태는 공통 환경 설정에서 읽습니다.

## 수용 기준

- 공개 값을 키보드로 채운 후 Enter → 제출 버튼 초점, 성공 콜백, 데모 ID만 저장되며 비밀번호가 비워집니다. 미입력 또는 다른 값 → 오류 설명과 첫 오류 초점, 세션 없음. [폼 단위 검사](../../src/pages/login/ui/login-page.test.tsx)의 두 시나리오가 확인합니다.
- 유효한 ID만 복원·다른 탭 분리·현재 탭 로그아웃, 사용할 수 없는 저장소의 메모리 대체와 브라우저 history 복귀 시 상태 재확인은 [세션 단위 검사](../../src/features/demo-session/model/session.test.ts)의 `tab demo session` 시나리오가 확인합니다.
- 라우트의 실제 복귀와 로그아웃 탐색, 한국어·영어 언어 메뉴, 모바일 확대·작은 화면에서 모든 행동 도달은 앱 브라우저 검증에서 확인합니다. 폼 단위 검사만으로 이 조합을 검증했다고 보고하지 않습니다.

# Users

<!-- page-route: /users -->

## 목적과 범위

워크스페이스 사용자 이름·이메일을 찾아 역할과 상태를 확인하고 수정합니다. 초대는 데모 디렉터리에 초대 대기 레코드를 생성합니다. 폼에 실제 이메일 발송 여부를 안내합니다. 운영 인증과 권한 집행은 서버 연결 시 별도 계약이 필요합니다. 본인 프로필은 계정 화면에서 확인합니다.

## 정보 구조와 주요 행동

페이지 헤더의 사용자 초대 버튼 아래에 검색·상태 필터와 사용자 목록을 둡니다. 이름 버튼으로 상세 Sheet를 열면 이메일, 역할, 상태를 확인할 수 있습니다. 다른 사용자의 상세에서는 접근 설정 수정 Dialog를 엽니다. 본인 상세에는 역할·상태 보호 안내를 표시합니다.

## 조회·조작 계약

- `q`는 이름·이메일 부분 문자열을 대소문자와 양끝 공백에 관계없이 검색합니다. 상태 `status`는 전체·활성·초대 대기·정지 중 하나입니다. 입력할 때 검색 기록을 교체하고 상태 변경과 상세 열기·닫기는 이력을 남깁니다. 필터 초기화는 상세 ID를 보존하고 검색 입력에 초점을 둡니다.
- `id`는 필터 밖 사용자도 상세 API로 조회합니다. 직접 링크·새로고침·뒤로/앞으로에서 같은 상세를 복원합니다. 상세 닫기는 목록 조건을 보존하고 열었던 이름 버튼 또는 검색 입력으로 초점을 돌립니다.
- 초대는 이름(양끝 공백 제거 후 1~80자), 이메일(254자 이하의 유효한 주소), 역할(관리자·구성원·뷰어)을 검증합니다. 새 레코드의 상태는 초대 대기입니다. 중복 이메일은 이메일 필드 오류로 표시하고 초안을 보존합니다. 성공하면 현재 필터를 유지한 채 생성된 사용자의 상세를 엽니다.
- 기존 사용자 편집은 역할·상태만 저장합니다. 본인 계정 `usr_demo`에는 편집 진입이 없고 데이터 경계에서도 본인 변경을 차단합니다. 변경하지 않은 편집은 저장 버튼이 비활성화됩니다. 대기 중에는 중복 제출·닫기·탐색을 차단하고, 수정한 초안을 취소·Escape·바깥 클릭·탐색으로 떠날 때 [미저장 입력 보호](../unsaved-changes.md)를 적용합니다.

## 상태별 화면

목록과 상세 각각 최초 조회는 skeleton, 오류는 안내·다시 시도, 캐시 재조회 실패는 기존 내용과 경고를 표시합니다. 필터 없는 전체 빈 디렉터리는 첫 초대 행동을 안내하고, 필터 결과가 비면 검색/상태를 해제할 수 있습니다. 없는 상세 ID는 사용자 없음과 목록 복귀를 표시합니다. 필드 오류는 해당 컨트롤에 연결하고 첫 오류로 초점을 옮깁니다. 저장 실패 시 입력을 보존하고 결과가 불확실한 오류에는 공통 재조회 안내를 사용합니다.

## 반응형 동작

| 구간              | 배치와 초점                                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 모바일 768px 미만 | 검색과 상태 필터를 한 열로 둡니다. 사용자 이름·이메일·역할·상태가 줄바꿈하며 상세와 편집창 내부에서 세로 스크롤할 수 있습니다. |
| 태블릿 768–1279px | 검색과 상태 필터를 두 열로 표시하고 목록은 사용자·역할·상태 세 열을 사용합니다. 상세는 오른쪽 Sheet입니다.                     |
| PC 1280px 이상    | 전체 너비 목록에서 같은 열로 역할·상태를 비교합니다. Dialog를 닫으면 초대 또는 상세의 수정 버튼으로 초점이 돌아옵니다.         |

긴 이름과 이메일은 행·상세 안에서 줄바꿈하고 텍스트 확대 시 버튼·필터·오류·저장 행동이 도달 가능해야 합니다.

## 상태 소유권과 구현 근거

URL 스키마는 [users search](../../src/pages/users/model/search.ts), 이름·이메일·상태 조합은 [목록 필터](../../src/pages/users/model/selectors.ts)가 소유합니다. [UsersPage](../../src/pages/users/ui/users-page.tsx)는 목록 Query와 URL 변경, [상세 Sheet](../../src/pages/users/ui/user-details-sheet.tsx)는 독립 상세 Query를 소비합니다. [workspace-user Query](../../src/entities/workspace-user/api/queries.ts)가 캐시·mutation 후 목록/상세 반영을 관리하고 [편집 feature](../../src/features/workspace-user-editor/ui/workspace-user-editor-dialog.tsx)가 폼 초안·검증 오류·저장 보호를 관리합니다.

## 수용 기준

- 잘못된 상태·ID는 기본값으로 복원하고, 이름·이메일 검색과 상태 필터를 조합해도 상세 ID는 유지합니다. [URL과 필터 단위 테스트](../../src/pages/users/model/search.test.ts)
- 초대할 때 잘못된 값·중복 이메일은 수정 가능한 필드에 오류를 표시합니다. 계속 편집·폐기와 저장 중 중복 제출·닫기·이동 보호는 [편집 폼 테스트](../../src/features/workspace-user-editor/ui/workspace-user-editor-dialog.test.tsx)가 확인합니다.
- 본인 상세 링크 복원과 편집 진입 차단, 초대 성공 후 새 상세 열기, 역할 저장 후 새로고침 지속성은 [브라우저 시나리오](../../e2e/workspace-users.spec.ts) `restores a user deep link and keeps demo invitations and access changes on reload`가 확인합니다.

## 목적과 범위

누가 무엇을 판단하거나 완료하는 화면인지 적습니다. 현재 구현된 기능과 데모·읽기 전용·운영 미구현 경계를 명시합니다.

## 정보 구조와 주요 행동

헤더 → 핵심 정보 → 보조 정보 → 상세/편집 순서와 주 행동, 보조 행동, 진입·종료 지점을 적습니다. [화면 조합](../design/compositions.md)을 선택하고 해당 화면의 차이를 기록합니다.

## 조회·조작 계약

각 컨트롤이 바꾸는 영역, 유지하는 값, 초기화·내보내기 범위를 적습니다. 조회 스키마의 기본값·타입은 소유 코드에 링크합니다. 기능이 없으면 없다고 명시합니다.

## 상태별 화면

최초 로딩, 캐시 재방문/재조회, 최초 오류/재조회 오류와 재시도, 전체 빈 데이터/필터 빈 결과, 저장 중·저장 실패를 구분합니다. 해당하지 않는 상태는 구현 근거와 이유를 적습니다.

## 반응형 동작

| 구간                | 배치·스크롤·초점                       |
| ------------------- | -------------------------------------- |
| 모바일 `< 768px`    | 주 행동, 목록→상세, 본문 넘침 처리     |
| 태블릿 `768–1279px` | 정보 밀도, 필터 줄바꿈, 표 내부 스크롤 |
| PC `≥ 1280px`       | 병렬 비교와 상세 배치                  |

[긴 콘텐츠](../design/content-overflow.md)에 따라 긴 이름·이메일·번역 문구의 축약 위치와 전체 내용을 확인할 경로를 적습니다.

## 상태 소유권과 구현 근거

실제 라우트·화면·model/Query 소유 파일의 로컬 inline 링크를 추가합니다. URL, Query, 임시 상태, 영구 환경 설정을 구분하고 해당하지 않으면 명시합니다. [URL 상태](../url-state.md), [Query 캐시](../query-cache.md)를 중복 정의하지 않습니다.

## 수용 기준

사용자 행동 → 관찰 가능한 결과와 기존 테스트 파일의 로컬 링크·시나리오 이름을 적습니다. 자동 검사가 없는 부분은 수동 확인 범위로 구분합니다. 실행 근거는 변경 작업의 결과에 기록합니다.

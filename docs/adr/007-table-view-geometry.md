# ADR 007: 기존 Table의 숫자 열 너비와 고정 위치

상태: 채택

## 맥락

Projects·Orders·Customers에서 사용자가 열 너비·순서·고정·표시와 행 간격을 바꾸는 기능을 제공한다. 열 너비는 드래그 또는 숫자 입력으로 결정되고, 왼쪽/오른쪽 고정 열의 위치는 현재 보이는 이웃 열의 너비 합으로 계산해야 한다. 숨김·이동·너비 변경 중에도 머리글·본문·로딩 행의 경계가 일치해야 한다.

기존 [Table](../../src/shared/ui/table.tsx)은 shadcn new-york/Radix registry에서 가져온 HTML table 조합이며 이미 `containerProps`로 표 내부 스크롤을 제공한다. 이 출처와 기존 보완 범위는 [ADR 002](002-shadcn-registry-adaptations.md)에 기록되어 있다. 이번 변경은 그 파일의 숫자 배치 API를 확장하며 별도 표 primitive나 UI 프레임워크를 만들지 않는다.

## 결정과 예외 범위

- `features/table-view`가 열 정의와 저장된 보기 상태를 검증하고, 보이는 열의 순서·숫자 너비·고정 위치를 계산한다. 화면은 공개 API만 사용하며 shared Table이 feature를 역으로 가져오지 않는다.
- 기존 `Table`은 `columnWidths`를 받아 `table`의 총 `width`와 `colgroup` 안 `col`의 각 `width`를 숫자로 적용한다. 이 값을 지정한 표는 `table-fixed`를 사용하고, 남는 컨테이너 폭에 열을 임의로 늘리지 않아 저장된 너비와 고정 위치의 합이 일치하도록 한다.
- 기존 `TableHead`·`TableCell`은 `layout`의 `pin`·`offset`·`edge`를 받는다. 고정된 `th`·`td`에는 숫자 `left` 또는 `right`만 적용한다. 보이는 고정 열의 누적 너비로 위치를 구하며 경계선·배경·초점·행 상태 표현은 Tailwind 의미 토큰을 유지한다.
- inline style 예외는 **`src/shared/ui/table.tsx` 안 `table`·`col`의 `width`와 `th`·`td`의 `left`/`right`**로 한정한다. 색상·글꼴·여백 등 다른 속성, 임의 DOM 요소, 호출부의 inline style, 새 `<style>` 블록은 허용하지 않는다. [예외 목록](../../scripts/ui-exceptions.mjs)에 이 정확한 파일을 기록하고 전용 가드레일로 속성·태그 범위를 검사한다.
- 행 간격은 세 가지 Tailwind 조합으로 적용한다. 컨트롤은 기존 shadcn Button·Checkbox·Input·Select·Dialog를 조합하고, `HStack`·`VStack`으로 배치한다. 새 의존성·CSS 파일·스타일 프레임워크를 추가하지 않는다.
- 실제 컨테이너 폭을 관찰해 고정 열 사이에 스크롤할 공간이 부족하면 고정을 일시 중단한다. 저장된 선택은 바꾸지 않고 폭이 확보되면 다시 적용한다. 표의 네이티브 터치 스크롤·키보드 접근과 로딩/오류/빈 상태의 바깥 크기를 유지한다. 이동·크기 드래그는 명시적인 머리글 핸들 안에서만 처리하며 표 전체 스크롤을 가로채지 않는다.

## 저장과 상태 경계

보기 설정은 `blueprint-table-views` 버전 1에 표 ID별로 저장한다. [Zod 스키마와 정규화](../../src/features/table-view/model/view-state.ts)가 형식·숫자 범위·열 ID를 검증하고, 현재 열 정의에 맞춰 알 수 없는 ID와 중복을 제거하며 잠긴 열과 필수 표시 열을 복구한다. 새 열은 기본 정의로 포함한다. [저장소](../../src/features/table-view/model/store.ts)는 잘못된 표 설정을 그 표의 기본값으로 복구하고, 지원하지 않는 버전은 기본값을 사용한다.

저장이 실패하면 [공통 환경 설정 저장소](../../src/shared/lib/preference-storage.ts)의 현재 탭 메모리로 계속 동작한다. 실제 계정별 서버 저장이나 기기 간 동기화는 제공하지 않는다. 검색·필터·정렬·페이지·상세 ID는 URL에 남고 행 데이터는 Query가 소유한다. **기본값 복원**은 해당 표의 보기 설정만 지운다. Overview의 최근 프로젝트 요약은 전체 Projects의 설정을 적용하지 않는다. 구체적인 복원·탐색 계약은 [URL 조회 상태](../url-state.md#표-보기-환경-설정)가 소유한다.

## 검토한 대안

| 대안                                     | 선택하지 않은 이유                                                                                                                                                |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 유한한 Tailwind 너비·위치 클래스 목록    | 드래그 결과의 정수 너비와 여러 고정 열의 누적 위치를 모두 표현하려면 큰 값 목록이 필요하다. 작은 구간으로 반올림하면 사용자가 지정한 너비와 실제 경계가 달라진다. |
| ref로 DOM의 style을 직접 변경            | React 상태와 실제 배치가 분리되고, 재렌더·숨김·고정·취소 시 복구 경로가 늘어난다. 선언적 배치 경계를 우회하므로 채택하지 않는다.                                  |
| 동적 CSS 변수 또는 `<style>` 문자열 생성 | 런타임 숫자를 전달하는 style 예외는 여전히 필요하며, 이 기능에 필요한 `width`·`left`·`right`보다 넓은 CSS 경계를 만들 이유가 없다.                                |
| 새로운 데이터 그리드·드래그 프레임워크   | 기존 TanStack Table·shadcn 구조와 별도의 primitive·의존성·접근성 체계를 유지해야 한다. 필요한 상태와 사용자 동작을 기존 조합으로 제공할 수 있다.                  |

## 검증과 재검토 조건

전용 아키텍처 가드레일은 Table 파일의 지정 태그·배치 속성을 허용하고 색상·임의 style 속성·다른 파일로의 예외 확장을 거부한다. 기존 FSD·컨트롤·색상 검사를 유지하며 검사 실패를 숨기기 위한 전역 제외를 추가하지 않는다. 정적 검사가 모든 런타임 숫자나 브라우저 배치를 증명하지는 않는다.

보기 상태·저장소 단위 검사는 잘못된 저장 형식, 알 수 없는 열, 잠긴 열, 너비 제한, 고정 순서, 초기화와 저장 불가 환경을 확인한다. 기존 브라우저 범주에서 보기 변경·새로고침 복원·초기화의 URL 보존, 열 경계와 고정 위치, 좁은 화면·키보드 동작을 확인한다. Projects의 요약 표와 전체 목록이 서로 영향을 주지 않는지도 검증한다. 전체 테스트와 빌드는 기존 Actions 실행 정책을 따르며 실제 실행 결과와 미실행 범위를 구분해 보고한다.

새 style 속성·다른 파일·다른 저장 범위가 필요해지면 이 예외를 자동 확장하지 않는다. 요구사항과 대안, 검사 범위를 다시 검토한다. registry 업데이트나 표 가상화·다중 머리글을 도입할 때는 현재 숫자 배치와 접근성 계약이 유지되는지 다시 확인한다.
